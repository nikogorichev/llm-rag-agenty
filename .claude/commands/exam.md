> $ARGUMENTS

# # Шаг 0 — Основывай экзамен на модуле README

- Приведи `$ARGUMENTS` к модулю в рамках `modules/00-setup` … `modules/08-capstone`
  (число вроде `04`, slug вроде `05-rag` или тему: tokenizer→01, integration→02,
  prompting→03, embeddings→04, rag→05, agents→06, production→07, capstone→08).
- Если `$ARGUMENTS` пустой, спроси, по какому модулю тестировать, затем продолжи.
- Прочитай `README.md` этого модуля. **Все вопросы должны основываться на том, что этот README реально преподаёт** (его концепции, задачи и критерии "Done when") — не проверяй материал, который модуль не охватывает. Если README ещё не существует, сообщи учащемуся, отступи к корневым `README.md` / `CURRICULUM.md`, чтобы определить предполагаемую область модуля, и отметь, что вопросы основаны на планируемой области.

# # Шаг 1 — Задай 5 вопросов, ONE ПО ОДНОМУ TIME (это ключевое поведение)

Задай **ровно один вопрос, затем STOP и жди ответа учащегося.** Не показывай следующий вопрос, ответ или оценку за текущий, пока он не ответит. В рамках 5 вопросов используй микс:

- ~2 **теоретических** ("объясни / почему / сравни") вопроса.
- ~1–2 вопроса **"что сделает этот код"** — покажи короткий фрагмент (используя стиль курса `get_provider()` / `getProvider()` и типы `llm_core`, где уместно) и попроси вывести результат или найти ошибку.
- ~1–2 **небольших задания по коду** ("напиши сигнатуру функции / основные 5 строк для X").

Нумеруй их (Вопрос 1 из 5, …). Подбирай сложность по маркерам глубины модуля (\U0001F7E2/\U0001F7E1/\U0001F534) — включи хотя бы один более сложный вопрос в стиле \U0001F534, если в модуле есть задачи \U0001F534.

Для каждого вопроса после ответа учащегося:

- Дай **краткую** обратную связь: отметь как Верно / Частично верно / Неверно, за 1–3 предложения скажи, что было правильно, а чего не хватило или что было неверно, и приведите ключевой факт. Будь лаконичен.
- Веди внутренний счёт для этого вопроса (используй частичные баллы, например, 0 / 0.5 / 1).
- Затем задавай следующий вопрос и снова жди.

Никогда не вываливай все пять вопросов сразу. Никогда не оценивай неотвеченный вопрос. Если учащийся говорит "пропустить" или "не знаю", дай ответ, поставь 0 баллов и переходи дальше.

# # Шаг 2 — Итоговый отчет

После того как на 5-й вопрос дан ответ и выставлена оценка, выведи:

1. **Балл: X / 5** (сумма баллов за вопросы) с однострочным вердиктом.
2. Краткий обзор по каждому вопросу (Q#: correct/partial/incorrect).
3. **Рекомендацию по учебе**, указывающую на **конкретные разделы README** (и дорожки глубины), которые учащемуся следует повторить по вопросам, в которых были ошибки, а также точную команду для запуска практики (`uv run python modules/<id>/py/...` или `pnpm tsx modules/<id>/ts/...`).

Будь ободряющим и конкретным на протяжении всего процесса. Цель — найти пробелы и направить учащегося к нужной части модуля, а не подловить его.
