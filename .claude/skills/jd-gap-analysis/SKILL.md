# JD → анализ разрыва с курсом (только темы ИИ)

Цель: имея описание вакансии, сообщить обучающемуся, какие навыки **AI/ML/GenAI** требуются для роли,
но этот `learn-ai` курс ещё не преподаёт — и куда вписывается каждый пробел.
Игнорируйте всё, что не является темой AI/ML.

Входные данные (`$ARGUMENTS` / аргументы, переданные навыку) — это либо необработанный **текст** JD, либо
**URL**. Если он пуст, попросите пользователя вставить текст JD или дать URL, затем остановитесь.

# # Шаг 1 — Получить текст JD

- **Вставленный текст** → используйте его напрямую.
- **URL** → получите его:
  1. Попробуйте `WebFetch(url, "Extract the full job description: responsibilities, requirements,
tech stack, nice-to-haves. Return the raw text.")`.
  2. Многие страницы вакансий (LinkedIn, Greenhouse, Lever, Workday, SPA компаний)
     отрисовываются через JavaScript, поэтому `WebFetch` возвращает только title/shell. Если результат выглядит
     пустым или обрезанным, отрисуйте его с помощью chrome-devtools MCP:
     `new_page(url)` → подождите → `evaluate_script(() => document.body.innerText)` и используйте этот
     текст. (Посмотрите, как gap analysis этого репозитория отобразил учебную программу SPA.)
  3. Если страница скрыта за wall'ом авторизации (часто на LinkedIn) или капчей, скажите об этом и попросите
     пользователя вместо этого вставить текст JD. Не угадывайте содержимое.

# # Шаг 2 — Извлечь требования, связанные с ИИ ONLY

Просканируйте JD и выберите конкретные элементы AI/ML/GenAI. **Оставьте** всё из этих категорий:

- **Фреймворки агентов / оркестрация:** LangChain (LCEL, memory, retrievers), LlamaIndex,
  Semantic Kernel, CrewAI, AutoGen, LangGraph, DSPy, Haystack, оркестрация агентов,
  автоматизация рабочих процессов, multi-agent, tool use / function calling, ReAct, планирование, MCP.
- **RAG / retrieval:** embeddings, векторные базы данных (Chroma, Qdrant, Pinecone, pgvector,
  Weaviate, FAISS), chunking, reranking, гибридный поиск (BM25 + dense), HyDE, GraphRAG,
  контекстуальный поиск, citations/attribution.
- **Интеграция LLM / prompting:** prompt engineering, few-shot, chain-of-thought,
  self-consistency, context engineering / оптимизация, структурированный вывод, стриминг,
  кэширование промптов, управление token/cost.
- **Fine-tuning / обучение:** SFT, LoRA / QLoRA / PEFT, RLHF, DPO, дистилляция, подготовка
  датасетов, overfitting/eval.
- **Eval / качество / безопасность:** LLM-as-judge, evaluation frameworks, guardrails,
  защита от prompt-injection, PII/DLP, Top 10 LLM от OWASP, red-teaming, обнаружение галлюцинаций,
  валидация с участием человека.
- **LLMOps / observability / serving:** трассировка (Langfuse, LangSmith, OpenTelemetry),
  мониторинг, regression gates, routing/fallbacks моделей, квантование, локальный inference,
  KV-кэш, serving AI за API (FastAPI/streaming/SSE для ИИ), batch API.
- **Модальности:** компьютерное зрение, мультимодальные LLM, CLIP, генерация изображений / диффузия,
  аудио / речь (STT/TTS, Whisper, realtime, VAD), компьютерное использование / браузерные агенты.
- **Основы / теория (часто проверяются на собеседованиях):** transformers/attention, токенизаторы,
  классическое ML (регрессия, bias-variance, метрики), deep learning (backprop, CNN, RNN),
  reasoning / вычисления во время теста, классификация.
- **Провайдеры / модели:** OpenAI, Anthropic/Claude, Gemini, Llama/Ollama, NVIDIA NIM,
  reasoning models, компромиссы model selection/cost.

**Исключите** (не пробелы ИИ): общая разработка ПО (git, REST, микросервисы, Docker,
Kubernetes, CI/CD, основы облака), если только это не инфраструктура specifically для _AI-serving;
владение языками программирования; основы databases/SQL (если это не text-to-SQL через LLM);
фронтенд-фреймворки; опыт работы; soft skills; степени; знания предметной области,
не связанные с ИИ (здравоохранение, финансы и т. д.) — отметьте домен, но это не сама тема курса.

Сформируйте чистый список извлеченных требований ИИ (дедуплицированных, нормализованных к словарю выше).

# # Шаг 4 — Сопоставление и отчёт

Для каждого извлечённого AI-требования классифицируйте:

- **Covered** — укажите module/task (например, "RAG → модуль 05; гибридный поиск → модуль 04
  Задача 4"). Если можно, процитируйте конкретную задачу.
- **Partial** — затронуто, но не на глубину, которую подразумевает JD; укажите, чего не хватает.
- **GAP** — не преподаётся.

Результат, в таком порядке:

1. **Краткое резюме** — фокус роли + количество AI-требований, количество пробелов.
2. **Таблица покрытия** — `| JD AI requirement | Status | Where (module/task) |`.
3. **Ранжированные GAPS** — сначала самые важные. Для каждого: что это, зачем это роли и
   конкретное предложение для нового module/task **в стиле этого репозитория**:
   - уровни глубины 🟢 app / 🟡 balanced / 🔴 from-scratch;
   - как на TypeScript, **так и** на Python;
   - код упражнений идёт через `llm_core` / `@learn-ai/llm-core` (никогда не хардкод вендора);
   - README с задачами + критерием "Готово, когда";
   - заглушки в TODO, которые **наводят на мысль**, а не отдают готовое решение (см. правило "Writing exercise
     scaffolds" в `CLAUDE.md`).
4. **Примечание по не-AI** — одна строка со списком заметных не-AI требований, которые вы намеренно исключили, и
   предметной областью роли, чтобы пользователь знал, что вы их не пропустили — просто это вне рамок.

# # Шаг 5 — Предложение по внедрению

Спросите, нужно ли внедрить основные пробелы. Если да, следуйте установленному рабочему процессу репозитория:
разрабатывайте в git workspace/worktree на основе `main`, поддерживайте py/ts параллельно, проверяйте, что
каждое упражнение запускается (временно заполните TODO-ы, запустите, проверьте приёмку), проводите adversary-ревью, затем
вливайте в рабочую ветку. Подключите любой новый модуль к `README.md` и `CURRICULUM.md`.

# # Правила

- **Только AI-темы.** Общее требование backend/devops/soft-skill никогда не является "пробелом".
- **Цитируйте, а не утверждайте.** Привязывайте каждый пункт "covered" к module/task; привязывайте каждый "пробел" к
  отсутствию его в `CURRICULUM.md` / `modules/`. Никогда не выдумывайте покрытие.
- Если курс уже охватывает то, что в JD названо другим словом (например, в JD указано
  "LangSmith", а в курсе трассировка преподаётся через Langfuse в модуле 07), отметьте это как **Covered
  (equivalent)** и назовите эквивалент.
