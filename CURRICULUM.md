Подробный учебный план для полного курса. Основным ориентиром для заданий и критериев приёма являются README модулей; этот документ — карта.

# # Как пользоваться этим курсом

1. Прочитайте README модуля перед написанием кода. В нём объясняется _почему_.
2. Сначала выполните задание 🟢 App. Заставьте что-то заработать. Затем возвращайтесь к 🟡/🔴.
3. Запустите код с двумя провайдерами и обратите внимание, что изменится. Абстракция провайдера — это намеренный педагогический инструмент — поймите, где она работает, а где протекает.
4. Используйте CLI `/tutor` в любой момент, чтобы задать вопросы или пройти оцениваемый тест по только что завершённому модулю (см. раздел «Applied Projects» ниже).
5. Воспринимайте чек-лист «Done when» как ваше определение завершённости работы — а не последнюю строчку написанного кода.

# # Module 01e — Trees & Ensembles

**Предварительные требования:** Module 01b. NumPy (базовая зависимость — ничего дополнительно).
Чистый numpy (Python) / простой TypeScript, полностью офлайн, детерминированно (фиксированные seed'ы, синтетические данные) — без провайдера, без сети, без LLM. **Без sklearn / без xgboost** — это ограничение и есть суть.

**Зачем:** Курс охватывает линейные модели (01b) и глубокие сети (01c), но ничего про деревья — а деревья решений / случайные леса / градиентный бустинг — это номер один в семействе тем для собеседований по классическому ML и базовый бейзлайн для табличных данных. Это дополнение с нуля реализует CART, бэггинг, случайный лес и градиентный бустинг с методом наименьших квадратов, а затем измеряет разложение смещения–дисперсии, объясняющее работу ансамблей.

**Цели обучения**- Реализуйте CART с нуля — индекс Джини, полный перебор срединных разбиений, рекурсивное построение, предсказание — и покажите влияние глубины на разрыв переобучения между обучающей и тестовой выборками.
- Реализуйте бутстрэп-выборку (≈ 63.2% уникальных строк), бэггинг и трюк с сэмплированием признаков в случайном лесу; покажите, что декоррелированный ансамбль превосходит как своего среднего представителя, так и одно глубокое дерево.
- Реализуйте градиентный бустинг с методом наименьших квадратов на регрессионных пнях — учитывая, что остаток (residual) является отрицательным градиентом (градиентный спуск в пространстве функций) — с монотонным MSE на обучении, U-образной кривой на валидации и ранней остановкой.
- Вычислите эмпирическое разложение смещения и дисперсии (bias–variance) по матрице предсказаний (M × N_test) и проверьте, что bias² + variance ≈ expected MSE − σ² для пня, глубокого дерева и глубоких бэггинг-деревьев.

**Tasks**

| #   | Task                                  | Depth | Что нужно сделать                                                                                                                         |
| --- | ------------------------------------- | ----- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Decision tree (CART) from scratch     | 🔴    | Реализуйте `gini`, `best_split` (каждый признак, каждая средняя точка), рекурсивное `build_tree`, `predict_one`; разрыв переобучения между глубоким деревом и деревом глубины 3. |
| 2   | Bagging → random forest               | 🟡    | Реализуйте `bootstrap_sample`, `train_forest` (bootstrap + подвыборка признаков для каждого разбиения через предоставленный тренер), `forest_predict`.     |

**Необходимые условия:** Модуль 05 (Задачи 1–2). Новых зависимостей нет — достаточно `uv sync`; граф в Задаче 4 реализован вручную. # # Модуль 13b — Посттренировка и выравнивание (RLHF & DPO)

**Предварительные требования:** Модуль 13 (и поможет Модуль 01b). NumPy (базовая зависимость —
ничего дополнительно не нужно). Чистый numpy (Python) / обычный TypeScript, полностью офлайн,
детерминированный — без провайдера, без сети, без LLM.**Зачем:** «Как на самом деле обучают ChatGPT?» — предобучение (pretraining) → SFT → оптимизация по предпочтениям (RLHF или DPO) — один из самых частых вопросов на собеседованиях по LLM, а 13-й модуль заканчивается на SFT. Это дополнение с нуля строит недостающий этап на игрушечных моделях: «ответы» — это синтетические векторы признаков, оцениваемые скрытой истинной наградой, а политики — это небольшие табличные функции softmax, поэтому каждый алгоритм остаётся наглядным: данные о предпочтениях → модель награды → RLHF (с его проблемой, reward hacking) → DPO.

- Реализовать алгоритм REINFORCE с базовой линией (baseline) для цели RLHF с KL-регуляризацией и продемонстрировать reward hacking (закон Гудхарта) с использованием KL-поводка и без него.
- Вывести и реализовать функцию потерь DPO и её аналитический градиент, проверенный с помощью вычисления градиента методом конечных разностей.

| 2   | Reward model (Bradley–Terry)      | 🟡    | Реализовать `bt_prob`, `bt_loss`, `bt_grad_step`; обучить линейную RM на зашумленных парах, проверить точность ранжирования + косинусную близость к w\*.            |
| 3   | RLHF (REINFORCE) + reward hacking | 🔴    | Реализовать `softmax`, `reinforce_step`, `kl_divergence`; оптимизировать несовершенную RM с KL-поводком и без него, наблюдать за эффектом Гудхарта.          |
| 4   | DPO from scratch                  | 🔴    | Реализовать `dpo_loss` и аналитический `dpo_grad` (проверенный методом конечных разностей); обучить на парах, следить за ростом отступа (margin) неявной награды. |

---## Глоссарий

**Attention (Механизм внимания)** — механизм, благодаря которому трансформер позволяет каждому токену «обращать внимание» на все остальные токены. Вычисляется как `softmax(QKᵀ/√dₖ)V`. Веса показывают, на какие токены смотрит каждая позиция, чтобы построить своё представление.

**Approval gate (Шлюз одобрения)** — UX-паттерн и механизм безопасности, при котором рискованное действие, инициированное ИИ (отправка письма, удаление данных, совершение платежа), приостанавливается и требует явного подтверждения человеком перед выполнением. Одноразовый токен выдаётся в момент запроса и потребляется при одобрении. Необходимость для агентных систем с побочными эффектами.

**ANN (Approximate Nearest Neighbour, Приближённый поиск ближайших соседей)** — алгоритм (например, HNSW), который находит ближайшие к запросу векторы без сравнения с каждым вектором в индексе. Достаточно быстр для миллионов векторов ценой редкого пропуска истинного ближайшего соседа.

**Agent (Агент)** — цикл, в котором LLM определяет, что делать, инструмент выполняет действие, результат возвращается как наблюдение, и LLM снова принимает решение до завершения задачи.

**Agent loop (Цикл агента)** — повторяющийся цикл, который harness (оболочка) выполняет в рамках одного шага (turn) агента: собрать контекст (system prompt, история, память, выводы инструментов) → вызвать модель для принятия решения → выполнить действие (tool call, ответ, запись состояния) → добавить трассировку и повторять, пока условие остановки не завершит запуск. Существует потому, что задачи дальнего горизонта не могут быть выполнены за один прямой проход (forward pass). Реализуется с нуля в модуле 06; укрепляется (условия остановки, детектирование застревания, идемпотентность) в модуле 06, задаче 6.

**A/B test (A/B-тестирование)** — сравнение двух вариантов на реальном трафике и использование статистического теста (например, двухпропорционального z-теста) для определения того, является ли наблюдаемая разница реальной или шумом. Требует понимания p-value, доверительных интервалов, мощности и ловушки множественного тестирования. Реализуется с нуля в модуле 01f.

**Bagging vs boosting (Бэггинг против бустинга)** — два способа объединения множества слабых моделей. Бэггинг (случайные леса) обучает деревья независимо на бутстреп-выборках и усредняет их — это снижает _дисперсию (variance)_. Бустинг (градиентный бустинг, XGBoost) обучает обучаемые элементы последовательно, каждый подстраивается под остатки предыдущего ансамбля — это снижает _смещение (bias)_. Модуль 01e реализует оба подхода с нуля.**BPE (Byte-Pair Encoding)** — алгоритм токенизации, который используется в большинстве современных LLM. Начинает с символов или байтов и многократно объединяет наиболее частую соседнюю пару в новый токен. Корректно обрабатывает редкие слова без проблемы выхода за словарный запас (out-of-vocabulary).

**Калибровка** — мера того, насколько хорошо оценки классификатора ведут себя как вероятности: среди примеров с оценкой `p = 0.8` около 80 % действительно должны быть положительными. Нейросети обычно излишне уверены; исправляется постфактум масштабированием по Платту или температурным масштабированием. См. заметки к интервью модуля 08.

**Чанк** — сегмент большого документа, созданный чанкером. Меньшие чанки дают более точный поиск; большие — больше контекста на каждый результат. Структурно-осознанные чанкеры разбивают текст по границам заголовков, а не по произвольному количеству символов.

**CLIP** — мультимодальная модель, обученная выравнивать изображения и текст в едином пространстве эмбеддингов. Позволяет классифицировать изображения без обучения (zero-shot) путём сравнения эмбеддингов изображений с эмбеддингами текстовых меток.

**Computer use** — возможность агента на базе LLM управлять GUI (браузером, рабочим столом ОС), делая скриншоты, классифицируя визуальное состояние и выдавая структурированные действия (клики, нажатия клавиш). Бета-версия computer use от Anthropic добавляет типы инструментов `computer_20241022`, `bash_20241022` и `text_editor_20241022`.

**Контекстное окно** — максимальное суммарное количество токенов (вход + выход), которые модель может обработать за один вызов. Превышение приводит к обрезке или ошибке. Управление бюджетом контекстного окна (подсчёт, усечение, уплотнение, кэширование) — тема модуля 16.

**Бюджет контекстного окна** — дисциплина отслеживания того, сколько токенов стоит каждая часть промпта (системный блок, документы, история, инструменты), и применения стратегий усечения или уплотнения до достижения лимита модели.

**Continual learning** — способность модели получать новые знания из потока данных с течением времени без полного переобучения и без катастрофического забывания. Связующее звено между циклом агента (который генерирует опыт как память) и обучающим циклом (который «запекает» опыт в веса): «обучение» внутри сессии — это извлечение, а не обновление весов. См. заметки к интервью модуля 06 и модуль 13b.**Continuous batching** — итеративное планирование (планирование на уровне итераций) в движках LLM-инференса (vLLM, TGI): завершённые последовательности покидают батч после каждого шага декодирования, а запросы из очереди добавляются немедленно, удерживая GPU полностью загруженным. Самый крупный прирост пропускной способности при продакшн-раздаче. См. заметки к интервью в модуле 14.

**Cosine similarity** — `dot(a, b) / (|a| × |b|)`. Измеряет угол между двумя векторами вне зависимости от их величины. Стандартная метрика расстояния для поиска по эмбеддингам.

**Decision tree (CART)** — классификатор или регрессор, который строится путём жадного выбора разбиения по признаку и порогу, максимально снижающего неоднородность (Gini), с рекурсией до достижения ограничения по глубине или размеру листа. Интерпретируемый, быстрый, базовый элемент случайных лесов и градиентного бустинга. Реализован с нуля в модуле 01e.

**Diffusion** — класс генеративных моделей, обучающихся обращать процесс зашумления. При обучении шум добавляется к изображениям по шагам (прямой процесс); модель учится удалять шум (обратный процесс). Используется в Stable Diffusion.

**Diarisation (speaker diarisation)** — задача сегментации аудиопотока по идентичности говорящего («кто и когда говорил?»), без предварительного знания дикторов. Применяется для создания расшифровок по каждому говорящему в записях с несколькими участниками.

**Distillation (knowledge distillation)** — обучение меньшей «student» модели имитировать распределение выходов большей «teacher» модели. Сокращает размер модели и стоимость инференса, сохраняя большинство преимуществ «teacher» по качеству. Используется в моделях вроде Stable Video Diffusion Turbo и во многих квантованных LLM.

**Document ingestion** — пайплайн, который преобразует исходные документы (PDF, HTML, Markdown, DOCX) в очищенные, структурированные текстовые чанки, готовые для эмбеддинга и поиска. Настоящая инженерная работа в RAG-проекте: около 80 % качества зависит от ingestion, а не от LLM.

**DPO (Direct Preference Optimization)** — настройка по предпочтениям, которая пропускает этап модели вознаграждения и RL-цикл: оптимальная политика в замкнутой форме для цели RLHF инвертируется так, чтобы собственные отношения логарифмических вероятностей LM выступали в качестве неявного вознаграждения, а потеря Bradley–Terry применяется непосредственно к парам (chosen, rejected). Реализовано с нуля в модуле 13b.**Drift** — деградация в продакшене без изменения кода. Data drift: изменяется распределение входных данных. Concept drift: меняется правильный ответ (устаревший корпус). Upstream drift: хостинг-провайдер незаметно меняет модель за псевдонимом. Обнаруживается путём сравнения референсного окна с текущим (PSI, KS-тест, расстояние между эмбеддингами). См. заметки из интервью модуля 21.

**Embedding** — вектор фиксированной длины из чисел с плавающей точкой, представляющий смысл текста (или изображения). Семантически похожие входы располагаются рядом в векторном пространстве.

**Encoder-only vs decoder-only** — одинаковые блоки трансформера, разные маски и цель обучения. Encoder-only (BERT): двунаправленное внимание + masked-LM → представления/эмбеддинги, не умеет генерировать. Decoder-only (GPT): причинная маска + предсказание следующего токена → генерация. Encoder–decoder (T5) объединяет оба подхода. В модуле 01d, задание 5, разница показана наглядно.

**Eval gate** — этап CI (скрипт, завершающийся с ненулевым кодом возврата), который блокирует слияние или развертывание, если метрика качества падает ниже порога. Эквивалент модульного теста, но для качества выхода LLM. См. модуль 21.

**F1 score** — гармоническое среднее точности и полноты: `2 × P × R / (P + R)`. Полезно при дисбалансе классов, когда важны как ложноположительные, так и ложноотрицательные результаты.

**Fine-tuning** — дообучение предобученной модели на меньшем, специфичном для задачи датасете для адаптации поведения. Дороже, чем промптинг, но может обеспечить более высокую точность на узких задачах.

**Hallucination** — ситуация, когда LLM генерирует правдоподобный, но фактический неверный контент, не основанный на предоставленном контексте.

**HNSW (Hierarchical Navigable Small World)** — ANN-алгоритм, используемый большинством продакшен-векторных баз данных (Chroma, Qdrant, Weaviate). Строит многослойный граф, обеспечивающий сублинейное время поиска.

**Hybrid search** — сочетание плотного (embedding) поиска и разреженного (BM25 / ключевое слово) поиска с последующим слиянием ранжированных списков (например, через RRF). Позволяет находить как семантические совпадения, так и точные запросы.**Идемпотентность (tool calls)** — присвоение каждому вызову инструмента, имеющему побочные эффекты, стабильного ключа перед выполнением, чтобы при повторной попытке после временного сбоя (сетевая ошибка, rate limit) запрос дедуплицировался вместо того, чтобы выполниться дважды (двойное письмо, двойная оплата). Инженерная задача на уровне оркестрации, а не на уровне модели. Модуль 06, Задание 6.

**KV cache** — в авторегрессионной генерации кэш матриц ключей (K) и значений (V) для всех предыдущих токенов. Позволяет избегать повторного вычисления внимания по всей истории на каждом шаге, снижая стоимость на токен в слое внимания с O(n) до O(1). Цена: память KV cache растёт вместе с длиной последовательности, и это основная причина, почему инференс на длинных контекстах дорог.

**LLM-as-judge** — использование LLM для оценки вывода другой LLM. Судье дается prompt оценить верность (faithfulness), релевантность или качество по шкале. Это дешевле человеческой разметки; важна калибровка.

**LLMOps** — операционная дисциплина развертывания и поддержки LLM-систем: версионированные наборы для оценки, регрессионные ворота, трекинг экспериментов, очереди человеческой ревью, продакшен-мониторинг и контроль затрат. Рассматривается в модуле 21.

**LoRA (Low-Rank Adaptation)** — техника parameter-efficient fine-tuning, которая замораживает базовую модель и добавляет небольшое число обучаемых низкоранговых матриц (ΔW = B·A, ранг r ≪ d). Позволяет выполнять fine-tuning на потребительском железе при ~100-кратном сокращении количества обучаемых параметров по сравнению с полным fine-tuning.

**Логистическая регрессия** — линейный классификатор, который применяет softmax к линейному преобразованию входа. Обучается с помощью градиентного спуска. Если на вход подается embedding, получается сильный baseline-классификатор.

**MCP (Model Context Protocol)** — открытый стандарт (Anthropic, 2024) для предоставления инструментов, ресурсов и промптов любому LLM-приложению. Один MCP-сервер мгновенно доступен любому MCP-клиенту (Claude Code, OpenAI Responses API, LangGraph и т. д.). Работает через stdio (подпроцесс) или HTTP/SSE (удалённый/мультиклиентский доступ).**Memory-aware agent (Агент с управляемой памятью)** — агент, чья инфраструктура (harness) активно управляет его когнитивным состоянием — кодирование, хранение, извлечение, внедрение, забывание — по типам памяти (эпизодическая история, семантические знания, процедурные рабочие процессы, сущности, свёртки), в отличие от просто memory-augmented agent, в который данные попадают только через внедрение контекста. Тема модуля 06d.

**MLE (Maximum Likelihood Estimation, метод максимального правдоподобия)** — выбор параметров, максимизирующих вероятность наблюдаемых данных. Минимизация перекрёстной энтропии — это и есть MLE при бернуллиевской/категориальной модели, а минимизация MSE — это MLE при гауссовском шуме — именно эти функции потерь используются по умолчанию. В модуле 01f эта связь раскрывается подробно.

**MoE (Mixture of Experts, смесь экспертов)** — вариация трансформера, в которой каждая FFN заменяется на E экспертных FFN плюс маршрутизатор, который активирует только top-k для каждого токена, поэтому общее число параметров (ёмкость) растёт, но не увеличивает вычисления (FLOPs) на токен. Mixtral 8×7B: ~47 B параметров всего, ~13 B активных. См. заметки к интервью в модуле 01d.

**Multimodal (Мультимодальный)** — модель или приложение, обрабатывающее более одной модальности (например, текст + изображения). GPT-4o и Claude 3+ — мультимодальные LLM.

**NDCG (Normalized Discounted Cumulative Gain)** — метрика ранжирования для градуированной релевантности: gain (выигрыш) дисконтируется с коэффициентом `1/log₂(rank+1)` и нормируется относительно идеального порядка. Используйте recall@k для настройки ретривера, MRR, когда достаточно одного хорошего фрагмента, и NDCG, когда релевантность градуирована. См. заметки по метрикам в модуле 05.

**OWASP LLM Top 10** — поддерживаемый сообществом список десяти наиболее критических угроз безопасности, специфичных для приложений с интеграцией LLM. Ключевые пункты: Prompt Injection (LLM01), Excessive Agency (LLM08) и Sensitive Information Disclosure (LLM06). Актуальный справочник — издание 2025 года; см. модуль 20.

**PagedAttention** — приём vLLM с виртуальной памятью для KV-кэша: разделение на блоки фиксированного размера с таблицей блоков на запрос, выделение по требованию, совместное использование блоков между запросами с общим префиксом. Сокращает потери кэша с ~60–80 % до <4 %, что позволяет формировать большие батчи, необходимые для continuous batching. См. заметки к интервью в модуле 14.**PCA (Principal Component Analysis)** — снижение размерности путём проецирования данных на главные собственные векторы ковариационной матрицы (направления максимальной дисперсии). Используется для визуализации эмбеддингов в 2D и для подавления шума признаков. Реализован с нуля в модуле 01f.

**Prompt caching** — функция провайдера, которая сохраняет KV-кэш длинного повторяющегося префикса (системный промпт, большой документ, определения инструментов), чтобы последующие вызовы переиспользовали его за малую долю обычной стоимости входных токенов. Anthropic использует явные точки останова `cache_control`; OpenAI кэширует автоматически для входов

> длиной от 1024 токенов.

**Prompt injection** — атака, при которой вредоносное содержимое во входных данных (например, полученный документ, веб-страница) переопределяет системный промпт или заставляет модель вести себя непреднамеренным образом. Прямая инъекция нацелена на пользовательское сообщение; косвенная инъекция маскирует инструкции в полученном содержимом.

**Quantization** — снижение числовой точности весов модели (например, с 32-битного float до 4-битного целого). Существенно уменьшает использование памяти при небольшом снижении качества. Позволяет запускать большие модели на потребительском оборудовании. GGUF — распространённый квантованный формат для llama.cpp/Ollama.

**RAG (Retrieval-Augmented Generation)** — паттерн, при котором релевантные фрагменты извлекаются из базы знаний и включаются в контекст LLM, чтобы модель могла отвечать с опорой на факты и цитаты, а не генерировать галлюцинации.

**ReAct** — паттерн промптинга (Reason + Act), при котором модель выводит структурированные строки `Thought / Action / Action Input`, которые цикл агента парсит, чтобы определить, какой инструмент вызвать.

**Reasoning model** — класс LLM (например, OpenAI o1/o3/o4, Anthropic extended thinking), который выделяет дополнительные вычислительные ресурсы на внутреннее обсуждение перед тем, как выдать видимый ответ. Обеспечивает более высокую точность на сложных многошаговых задачах ценой большей задержки и стоимости. См. модуль 15.

**Reranking** — второй этап извлечения, который берёт top-k кандидатов от быстрого ретривера и оценивает их с помощью более точной, но медленной модели (cross-encoder или LLM). Улучшает точность без потери полноты.**Responses API** — API агентской платформы OpenAI (январь 2025), которое добавляет
цепочку ответов через `previous_response_id`, размещаемые инструменты (web_search,
code_interpreter, file_search) и удалённый коннектор MCP. Рассматривается в модуле 17.

**Reward model** — модель, обученная на парных человеческих предпочтениях (Брэдли–Терри:
`P(a ≻ b) = σ(r_a − r_b)`) для оценки ответов, замещающая человека в ходе
RLHF. Изначально несовершенна — жёсткая оптимизация по ней ведёт к reward hacking
(закон Гудхарта), поэтому RLHF удерживает модель на «поводке» KL относительно референсной политики.
Создаётся с нуля в модуле 13b.

**RLHF (Reinforcement Learning from Human Feedback)** — этап посттрейнинга,
превращающий SFT-модель в выровненного ассистента: собираются пары предпочтений,
обучается reward model, затем политика оптимизируется методами RL (PPO в проде)
по критерию `reward − β·KL(π‖π_ref)`. Пайплайн, лежащий в основе моделей типа ChatGPT;
в модуле 13b собирается игрушечная версия end to end, включая reward hacking.

**Scaling laws** — эмпирические степенные законы, связывающие лосс с количеством параметров,
данных и вычислений (Kaplan et al.); Chinchilla показала, что вычислительно оптимальное
обучение требует ~20 токенов на параметр, а современные модели намеренно перетренировываются
сверх этого, так как dominates inference cost. См. заметки к интервью в модуле 01d.

**Semantic tool discovery** — индексация определений инструментов в векторном хранилище
(эмбеддинги дополненных LLM описаний, а не только сигнатур) и передача модели на запрос
только top-k релевантных схем вместо перечисления всех инструментов. Решает проблему
перегрузки tool-schema: точность выбора падает, а стоимость токенов растёт по мере
увеличения списка схем. Модуль 17, задание 6.

**Speculative decoding** — небольшая черновая модель предлагает k токенов, целевая модель
проверяет их за один параллельный прямой проход, а правило rejection-sampling сохраняет
распределение выхода в точности равным целевому. Безпотерное ускорение декодинга в 2–3 раза.
См. заметки к интервью в модуле 14.

**Streaming UX** — продуктовый паттерн, при котором вывод LLM отображается токен за токеном
по мере генерации, а не по завершении всего ответа. Существенно снижает воспринимаемую задержку.
Реализуется через Server-Sent Events (SSE) или WebSockets.
См. модуль 22.**Temperature** — параметр семплирования, который делит логиты перед применением softmax.
`T < 1` делает вывод более детерминированным; `T > 1` — более случайным.
`T = 0` приблизительно соответствует жадному выбору (greedy).

**Test-time compute** — дополнительные вычисления во время инференса (до генерации ответа или в процессе) для повышения точности: цепочка рассуждений (chain-of-thought), самосогласованность (self-consistency), best-of-N семплирование, циклы самокоррекции или полноценное «обсуждение» в reasoning-моделях. См. модуль 15.

**Text-to-SQL** — задача преобразования естественноязыкового вопроса в корректный SQL-запрос при наличии схемы базы данных. Требует промптинга, привязанного к схеме, проверок безопасности (white-list для чтения, отклонение вложенных запросов) и самовосстановления при ошибках выполнения. Рассматривается в модуле 12.

**Token** — базовая единица, с которой работает языковая модель. Обычно это фрагмент слова (sub-word); частые слова — один токен, редкие могут состоять из нескольких. Стоимость и контекстное окно измеряются в токенах.

**Tool calling** — механизм, с помощью которого LLM запрашивает выполнение внешней функции. Модель возвращает структурированный вызов (имя + аргументы); хост выполняет его и возвращает результат как новое сообщение.

**Tool-output offloading** — сохранение громоздкого результата инструмента в хранилище логов и вставка в контекст только однострочной ссылки (`[Tool Log #id] …`) плюс инструмента `read_tool_log`, чтобы следующие итерации цикла не переносили тысячи устаревших токенов. Держит контекст агента плоским вместо монотонного роста. Модуль 16, задача 6.

**Top-p (nucleus sampling)** — сохраняется минимальное множество токенов, сумма вероятностей которых ≥ p, производится перенормировка и семплирование. Порог отсечения адаптируется к форме распределения динамически.

**VAD (Voice Activity Detection)** — задача обработки сигналов: классификация кадров аудиопотока как содержащих речь или тишину. Базовый энергетический метод вычисляет RMS по кадрам и сравнивает с порогом относительно пиковой энергии. Более сложные подходы (WebRTC VAD, Silero) используют модели GMM или LSTM.

**Vector DB** — база данных, оптимизированная для хранения и запросов высокоразмерных векторов с помощью ANN-поиска, с поддержкой персистентности, фильтрации по метаданным и мультиарендности. Примеры: Chroma, Qdrant, Weaviate, Pinecone.
