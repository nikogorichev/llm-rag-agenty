# RAG (RAG)

Большие языковые модели имеют фиксированную дату отсечения знаний и могут галлюцинировать факты, отсутствующие в их обучающих данных. **RAG (Retrieval-Augmented Generation) (RAG)** решает эту проблему, подключая модель к внешней базе знаний во время инференса. Вместо того чтобы просить модель вспомнить факт, вы извлекаете релевантный документ и помещаете его прямо в промпт.

# # Пайплайн RAG

Стандартный пайплайн RAG состоит из двух этапов:

## # Индексация (офлайн)
1. **Разбейте** исходные документы на чанки (обычно по 200–500 токенов с некоторым перекрытием для сохранения контекста на границах чанков).
2. **Получите эмбеддинги** для каждого чанка с помощью модели эмбеддингов, чтобы получить плотный вектор.
3. **Сохраните** векторы и исходный текст в векторной базе данных (например, Chroma, Qdrant или в индексе в памяти для прототипирования).

## # Поиск + генерация (онлайн)
1. **Получите эмбеддинг** запроса пользователя, используя ту же модель эмбеддингов.
2. **Извлеките** топ-k чанков, векторы которых наиболее похожи на вектор запроса (поиск ближайших соседей).
3. **Переранжируйте** (опционально): кросс-энкодер заново оценивает топ-k кандидатов для повышения точности. BM25 поиск по ключевым словам можно комбинировать с dense-поиском (**hybrid search**), чтобы находить точные совпадения по ключевым словам, которые пропускает семантический поиск.
4. **Сгенерируйте**: вставьте извлеченные чанки в промпт в качестве контекста и попросите LLM ответить на вопрос, ссылаясь только на то, что есть в контексте.

# # Основные типы сбоев

- **Retrieval miss** (ошибка поиска): ответ есть в корпусе, но эмбеддинг запроса слишком несхож с эмбеддингом чанка — настройка размера чанка и перекрытия помогает.
- **Слишком длинный контекст**: включение слишком большого количества извлеченных чанков может вытеснить релевантный отрывок за пределы эффективного диапазона внимания модели.
- **Галлюцинации несмотря на поиск**: модель игнорирует контекст и генерирует ответ из памяти. Явные указания в промпте ("отвечайте только на основе предоставленного контекста") снижают, но не устраняют эту проблему.

# # ОценкаТочная система RAG должна оцениваться по двум осям: **полнота поиска (retrieval recall)** (был ли извлечен нужный чанк?) и **верность ответа (answer faithfulness)** (следует ли сгенерированный ответ из извлеченного контекста?). Метрики вида LLM-as-judge и фреймворки, такие как RAGAS, автоматизируют оба эти процесса.
