# Интерактивное обучение: `/tutor`, `/exam` и CLI-утилита `tutor`

В этом курсе реализовано **два** способа интерактивного обучения — тьютор, который отвечает на вопросы и подсказывает следующий шаг в коде, и экзамен, который проверяет ваши знания по модулю и выставляет оценку. Оба инструмента **основаны на README-файлах модулей** (уроках), поэтому они преподают *именно этот* курс, а не общие сведения об ИИ.

Они доступны в двух вариантах:

| | **Слэш-команды Claude Code** | **Автономный CLI** |
| --- | --- | --- |
| Что | `/tutor`, `/exam` | `uv run python -m tutor ask` / `exam` |
| Где | Внутри Claude Code, в этом репозитории | Любой терминал — Claude Code не требуется |
| Модель | Та, что запущена в Claude Code | Та, что задана в `LLM_PROVIDER` |
| Стоимость | Согласно вашему тарифу Claude Code | **Бесплатно** на локальном Ollama (по умолчанию) |
| Читает ваши файлы | **Да** — читает и проверяет ваш код упражнений | Нет (работает только на основе README) |
| Для чего | Глубокая помощь при кодинге; code review | Быстрое изучение/тест, офлайн, нулевая стоимость |

**Общее правило:** если вы работаете в Claude Code и хотите помощь *с вашим реальным кодом*, используйте слэш-команды. Если вы просто хотите поучиться или протестировать себя — особенно бесплатно и локально — используйте CLI.

# # Вариант A — Слэш-команды Claude Code

Это файлы промтов в папке `.claude/commands/`. Вводите их в Claude Code, находясь в этом репозитории.

## # `/tutor [номер_модуля или тема] <вопрос>`

Терпеливый тьютор. Он читает соответствующий README модуля, а затем:

- На вопросы по **понятиям** (concepts) он отвечает *в сократовском стиле* — дает интуитивное понимание и легкий толчок, а не вываливает стену текста.
- На вопросы вида **«как мне двигаться дальше»** он отвечает *конкретно* — упорядоченный план следующего шага реализации, распространенные ошибки и команду для проверки.
- Он предложит **прочитать и проверить ваши файлы** в этом модуле согласно чек-листу «Done when».
- Он не выдаст полное решение, если вы сами об этом не попросите.

Примеры:```text
/tutor 04 how do embeddings turn text into vectors I can compare?
/tutor 05 I implemented chunk→embed→retrieve, what do I build next?
/tutor 01 review my BPE tokenizer
```### `/exam <номер модуля или тема>`

Интерактивный тест по модулю. Он считывает README, затем задаёт **5 вопросов по одному** (смесь концептуальных вопросов, «что сделает этот код» и небольших задач по написанию кода), **ждя вашего ответа** перед каждым следующим вопросом. Он оценивает каждый ответ с кратким комментарием и завершает **итоговой оценкой из 5 баллов**, а также даёт рекомендации по изучению с указанием конкретных разделов README.

Примеры:```text
/exam 04
/exam rag
```## Вариант B — автономный CLI `tutor`

Находится в [`projects/tutor/`](../projects/tutor/). Те же два принципа, но он запускается в любом терминале и взаимодействует с моделями через клиент `llm_core` курса — так что по умолчанию работает **бесплатно на локальной модели Ollama** (или с любым провайдером, настроенным через `LLM_PROVIDER`). Он не видит ваш код; работает исключительно на основе README модулей.```bash
uv sync                       # once, from the repo root
ollama pull llama3.2          # zero-cost path
ollama pull nomic-embed-text  # optional, improves question retrieval

cd projects/tutor             # run it from its own dir (like the news-agent)

# Q&A REPL — ask anything; it grounds answers in the most relevant README(s)
uv run python -m tutor ask
uv run python -m tutor ask --module 05     # focus a module

# Graded quiz on a module (by id, slug, or topic)
uv run python -m tutor exam --module 04
uv run python -m tutor exam --module rag --num 3 --difficulty hard

# See what modules exist
uv run python -m tutor modules
```Внутри `ask` REPL: `:module <id>` — для фокусировки на модуле, `:modules` — для их списка, `:help` — для справки по командам, `:quit` — для выхода.

Этот CLI также является **рабочим примером** паттернов, которые вы реализуете в курсе: лёгкий шаг **RAG**-извлечения (поиск нужного README) для формирования ответа и оценивание по схеме **LLM-as-judge** в режиме экзамена. После прохождения модулей 05 (RAG) и 07 (production) прочитайте `projects/tutor/tutor/content.py` и `exam.py` — они станут понятны.

# # Как Tutor отвечает на вопросы и проводит квизы

Обе формы работают по одной схеме:

1. **Найти модуль.** По теме или номеру урока находится файл `modules/<id>/README.md`. (CLI использует сходство ключевых слов и эмбеддингов для автоматического выбора; слэш-команда рассуждает над этим. Если README ещё не написан, оба варианта сообщают об этом и переключаются на корневые файлы `README.md` / `CURRICULUM.md` вместо того чтобы выдумывать содержимое.)
2. **Опора на README.** Текст урока подаётся в качестве контекста, чтобы ответы и вопросы квиза соответствовали тому, что *реально* преподаёт этот курс, включая его конвенции: абстракцию `llm_core` / `@learn-ai/llm-core`, уровни глубины (🟢 app / 🟡 balanced / 🔴 from-scratch) и способы запуска (`uv run python …`, `pnpm tsx …`).
3. **Tutor:** объясняет на нужном уровне **и** советует конкретный следующий шаг по коду. **Exam:** генерирует вопросы, задаёт их по одному, оценивает ваши ответы и сообщает результат с рекомендациями по изучению, которые отсылают вас обратно к README.

# # Что выбрать?

- **Зашли в тупик при написании кода, хотите ревью файлов** → `/tutor` в Claude Code.
- **Хотите проверить себя и узнать слабые места** → используйте `/exam` или `uv run python -m tutor exam`.
- **Офлайн, в самолёте или нужно всё бесплатно/локально** → CLI `tutor` на Ollama.
- **Просто изучаете концепцию** → любой вариант; `ask` REPL в CLI обеспечивает быстрый цикл работы.
