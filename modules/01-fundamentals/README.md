# # Concepts

## # 1. Токены и токенизация

Модели не читают символы или слова. Они читают **токены** — целочисленные идентификаторы из фиксированного словаря, где каждый идентификатор обозначает фрагмент текста (часто субслово). `" tokenization"` может быть одним токеном, а `" antidisestablishmentarianism"` — пятью. Прежде чем текст попадет в сеть, он _токенизируется_ (разбивается) в идентификаторы; после этого предсказанные идентификаторы _декодируются_ обратно в текст.

Почему субслова, а не целые слова? Словарь целых слов не сможет записать то, чего никогда не видел (каждая опечатка, каждое новое имя = неизвестное слово). Словарь символов не имеет проблемы с неизвестными словами, но делает последовательности чудовищно длинными. **Byte-Pair Encoding (BPE)** — это компромисс, который используют все: начинаем с байтов/символов, затем многократно объединяем наиболее частую соседнюю пару в новый токен. Распространенные слова сжимаются в один токен; редкие слова изящно разбиваются на части; ничего не является полностью неизвестным, потому что всегда можно опуститься до уровня байтов.

Это важно на практике: количество токенов = стоимость и = бюджет контекстного окна. «Сделай короче» иногда означает «используй меньше токенов», что не то же самое, что «меньше символов» (пробелы, регистр и редкие слова стоят дополнительно).

## # 2. Embeddings и векторная похожесть**Эмбеддинг** (embedding) — это вектор фиксированной длины из чисел с плавающей точкой, который представляет собой _смысл_ фрагмента текста. Модель обучается так, чтобы тексты со схожим смыслом располагались близко друг к другу в этом многомерном пространстве. «Как мне сбросить пароль?» и «Я забыл логин» оказываются рядом, а «Кот сел на коврик» — далеко.

«Близость» измеряется с помощью **косинусного сходства** (cosine similarity) — косинуса угла между двумя векторами, без учёта их длины:```
cos(a, b) = (a · b) / (‖a‖ · ‖b‖)
```- `a · b` — это скалярное произведение: `Σ aᵢbᵢ`.
- `‖a‖` — это длина вектора: `√(Σ aᵢ²)`.
- Результат находится в диапазоне `[-1, 1]`: **1** = одинаковое направление (очень похоже), **0** = ортогональны (не связаны), **-1** = противоположное.

Мы делим на длины, потому что нас интересует _направление_ (смысл), а не сама длина вектора. Эта одна функция — движок семантического поиска и RAG (модули 04–05).

## # 3. Внимание (scaled dot-product)

Внимание — это механизм, благодаря которому трансформер позволяет каждому токену «смотреть» на другие токены и подтягивать релевантный контекст. Для каждого токена вычисляются три вектора с помощью обучаемых проекций:

- **Q** (query): что этот токен ищет.
- **K** (key): что предлагает каждый токен.
- **V** (value): фактическое содержимое, которое вносит каждый токен.

Выход для токена представляет собой _взвешенное среднее всех V-векторов_, где веса определяются тем, насколько хорошо Q этого токена совпадает с K каждого токена:```
Attention(Q, K, V) = softmax( (Q · Kᵀ) / √dₖ ) · V
```Пошагово, для длины последовательности `n` и размерности головы `dₖ`:

1. `scores = Q @ Kᵀ` → матрица `n × n`; `scores[i][j]` показывает, насколько токен _i_
   обращает внимание на токен _j_ (исходное скалярное произведение).
2. **Масштабирование** на `1/√dₖ`. Без этого большой `dₖ` делает скалярные произведения огромными, что
   загоняет softmax в режим, близкий к one-hot, с затухающими градиентами. √dₖ
   поддерживает дисперсию на приемлемом уровне.
3. Применить **softmax** к каждой строке → веса для строки _i_ становятся неотрицательными и в сумме дают 1.
   `softmax(x)ᵢ = exp(xᵢ) / Σⱼ exp(xⱼ)`. (Вычтите максимум из строки перед `exp` для
   численной стабильности — тот же результат, без переполнения.)
4. `output = weights @ V` → выход каждого токена — это взвешенная вниманием смесь всех value-векторов.

Это _одна голова_. Реальные модели запускают много голов параллельно (каждая может специализироваться:
на синтаксисе, кореференции и т.д.) и используют стек из множества слоёв. Но суть — в четырёх шагах
выше, и это просто умножения матриц плюс softmax.

## # 4. Сэмплинг (превращение логитов в токен)

Последний слой модели выводит **логит** для каждого токена словаря —
ненормализованную оценку. Чтобы выбрать следующий токен, нужно сначала превратить логиты в
распределение вероятностей с помощью softmax, а затем _сэмплировать_ из него. Способ сэмплирования
определяет, насколько «творческим» или «сфокусированным» будет вывод:

- **Greedy** (argmax): всегда брать токен с наивысшей вероятностью. Детерминированный подход,
  может стать повторяющимся/скучным.
- **Temperature**: разделить логиты на `T` перед softmax. `T < 1` делает распределение более острым
  (более уверенным, более детерминированным); `T > 1` делает его более плоским (более случайным, более
  разнообразным); `T → 0` приближает к greedy.
- **Top-k**: оставить только `k` токенов с наивысшей вероятностью, перенормировать и сэмплировать
  из них. Ограничивает глубину падения в «хвост» распределения.
- **Top-p (nucleus)**: отсортировать по вероятности, оставить наименьший набор, чья суммарная
  вероятность ≥ `p`, перенормировать и сэмплировать. Адаптирует порог отсечения к форме
  распределения (на уверенном шаге остается мало токенов, на неуверенном — много).На практике их комбинируют (например, `temperature` + `top-p`). Понимание этих механизмов развеивает магию вокруг настроек `temperature` / `top_p`, с которыми вы столкнетесь при каждом вызове API (интерфейса программирования приложений).

## # 5. Что такое «языковая модель»?

Если отбросить хайп, то языковая модель — это одно и то же: **предсказатель следующего токена**. Получив последовательность токенов, она выдает распределение вероятностей для следующего токена. Генерация — это просто: предсказать распределение → сэмплировать один токен (раздел 4) → добавить его → повторить. «Понимание», «рассуждение» и «чат» — всё это возникающее поведение, результат того, что предсказание выполняется очень хорошо на огромном словаре и контексте.

Простейшая возможная версия — это **модель биграмм**: подсчитываем, как часто каждый токен следует за другим в корпусе, и предсказываем следующий токен, основываясь только на этих частотах (без нейросети, без механизма внимания). Это ужасная языковая модель — но она _настоящая_, и написание такой модели делает понятие «предсказание по контексту» осязаемым.
