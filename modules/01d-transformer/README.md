# # Концепции

## # 1. Масштабированное скалярное внимание (Scaled dot-product attention)

Внимание позволяет каждому токену извлекать информацию из любого другого токена. На основе трёх матриц, полученных из входных данных, — **запросов** `Q`, **ключей** `K`, **значений** `V` — выходным значением является взвешенное среднее векторов значений, причём веса определяются тем, насколько хорошо каждый запрос соответствует каждому ключу:```
scores  = Q @ Kᵀ / √d_k        # (n_q × n_k) raw affinities
weights = softmax(scores)       # row-wise; each row sums to 1
output  = weights @ V           # (n_q × d_v)
```**Зачем делить на √d_k?** Скалярное произведение двух `d_k`-мерных векторов имеет дисперсию, пропорциональную `d_k`. Без масштабирования большой `d_k` смещает оценки в хвосты распределения softmax, где градиенты исчезают, а распределение схлопывается на один токен. Деление на `√d_k` удерживает оценки в единичном масштабе, чтобы softmax оставался «мягким».

**Численно стабильный softmax** — вычтите максимум в строке перед возведением в степень (тот же результат, без переполнения):```
softmax(z)_j = exp(z_j − max(z)) / Σ_k exp(z_k − max(z))
```### 2. Causal masking (каузальная маскировка)

Декодер генерирует слева направо, поэтому позиция `i` никогда не должна обращать внимание на _будущую_ позицию `j > i` (это было бы читерством — подсматриванием ответа). Мы реализуем это с помощью **аддитивной маски**, добавляемой к скорам перед softmax:```
mask[i, j] = 0        if j ≤ i     (allowed)
mask[i, j] = −∞       if j > i     (blocked)
````exp(−∞) = 0`, поэтому каждый будущий вес становится в точности равным 0, а сумма строки по допустимым позициям остаётся равной 1. В коде мы используем большое отрицательное число (например, `−1e9`) вместо `−∞`.

## # 3. Многоголовое внимание

Одна голова внимания может усреднять данные только одним способом. **Многоголовое** внимание выполняет `h` независимых операций внимания параллельно, каждая в своём подпространстве `d_k = d_model / h`, так что разные головы могут специализироваться (например, одна отслеживает синтаксис, другая — дальние кореферентные связи и т. д.):```
Q, K, V = X @ W_q,  X @ W_k,  X @ W_v      # each (n × d_model)
for each head h:  slice its d_k columns, run scaled dot-product attention
concat the h head outputs  →  (n × d_model)
output = concat @ W_o                       # final mix across heads
```При `h = 1` и тождественных проекциях (identity projections) это сводится к обычному single-head attention — полезная проверка корректности.

## # 4. Позиционное кодирование (Positional encoding)

Механизм внимания является **эквивариантным к перестановкам** (permutation-equivariant): он не имеет понятия порядка. Если перемешать входные токены, выходы перемешаются так же — фразы "dog bites man" и "man bites dog" были бы неразличимы. Мы вводим информацию о порядке, **добавляя** к эмбеддингу каждого токена перед механизмом внимания вектор, зависящий от позиции. Схема синусоидального PE (Positional Encoding):```
PE[pos, 2i]   = sin( pos / 10000^(2i/d) )
PE[pos, 2i+1] = cos( pos / 10000^(2i/d) )
```Чётные размерности используют синусы, нечётные — косинусы, а длина волны растёт геометрически вдоль оси размерностей (быстрые колебания в начале, медленные — позже). Два следствия, которые вы проверите: каждое значение лежит в `[−1, 1]`, и **скалярное произведение PE максимально на нулевом расстоянии и в целом убывает для близких смещений** — тест проверяет соседнюю пару относительно конца последовательности. (Спад не является строго монотонным для _всех_ пар позиций — сумма синусоид может колебаться — но локальный тренд даёт модели плавное ощущение расстояния.)

## # 5. LayerNorm, остаточные связи и feed-forward сеть

**LayerNorm** нормализует вектор признаков каждого токена к среднему 0 и дисперсии 1, затем применяет обучаемый масштаб `γ` и сдвиг `β` (в отличие от BatchNorm (Batch Normalization) он работает для каждого токена, поэтому не зависит от размера пакета):```
μ    = mean(x)                    # over the feature axis, per row
σ²   = mean((x − μ)²)
x̂    = (x − μ) / √(σ² + ε)
out  = γ · x̂ + β
```**GELU (Gaussian Error Linear Unit)** — это гладкая функция активации, используемая в моделях семейства GPT (аппроксимация tanh):```
gelu(x) = 0.5 · x · (1 + tanh( √(2/π) · (x + 0.044715 · x³) ))
```**FFN** (позиционная сеть прямого распространения) применяет к каждой позиции один и тот же двухслойный MLP (многослойный перцептрон), обычно расширяясь до `4 × d_model` в середине:```
h = gelu(x @ W1 + b1)      # (n × d_model) → (n × d_ff)
y = h @ W2 + b2            # (n × d_ff) → (n × d_model)
```**Блок Pre-LN.** GPT-2 и последующие модели нормализуют _вход_ каждого подслоя и добавляют вокруг него residual connection. Чистый residual path (вход проходит напрямую, подслой лишь добавляет поправку) — именно это позволяет глубоким стекам обучаться стабильно:```
x = x + MHA(LN1(x), causal_mask)      # attention sublayer
x = x + FFN(LN2(x))                   # feed-forward sublayer
```Возьмите N таких блоков — и получится декодер.

## # 6. KV-кэш

Генерация авторегрессионная: по одному токену за раз, причём каждый токен делает attention по всему накопленному префиксу. **Наивный** подход пересчитывает ключи и значения для _всего_ префикса на каждом шаге — чтобы сгенерировать `n` токенов, требуется `1 + 2 + … + n = n(n+1)/2` проекций ключей (квадратичная сложность). Но ключи и значения старых токенов никогда не меняются.

**KV-кэш** хранит `k` и `v` каждого токена ровно один раз. На шаге `t` вы вычисляете `q, k, v` только для нового токена, добавляете `k, v` в кэш и выполняете attention для нового запроса по всем кэшированным ключам и значениям:```
naive : n(n+1)/2 key projections   (recompute prefix each step)
cached : n key projections          (one new key per step)
```Одинаковые выходные данные, линейная сложность вместо квадратичной. Именно поэтому настоящий инференс LLM (Large Language Model) происходит быстро — и почему более длинный контекст пропорционально увеличивает затраты памяти (кеш растет).

## # 7. Энкодер vs декодер — BERT vs GPT

Классический вопрос на собеседовании «в чем разница между BERT и GPT?» имеет на удивление простой ответ: **оба — это стопки из тех самых блоков трансформера, которые вы собирали выше**. Отличаются лишь **маска внимания (attention mask)** и **цель обучения (training objective)** — и всё остальное (в чем силен каждый из них) вытекает из этих двух решений.

- **Только энкодер (BERT).** Без маски: внимание **двунаправленное (bidirectional)**, каждая позиция видит всю последовательность, слева _и_ справа. Обучается с целью **masked-LM** — скрыть ~15% токенов, предсказать их по полному двустороннему контексту. Результат — отличные контекстные _представления (representations)_ (каждая позиция суммирует всё своё окружение), но модель не может генерировать текст слева направо: для двунаправленной генерации токена `t` потребовалось бы уже знать токены `> t`.
- **Только декодер (GPT).** **Каузальная маска (causal mask)** из Задания 1: позиция `i` видит только `j ≤ i`. Обучается с целью **next-token** — предсказать токен `t+1` по токенам `0..t`. Именно это делает возможной авторегрессивную генерацию (и то, что KV-кеш из Задания 4 ускоряет), ценой того, что при представлении позиции никогда не используется контекст справа.
- **Энкодер–декодер (T5, исходный трансформер).** Двунаправленный энкодер считывает вход; каузальный декодер генерирует выход, используя **cross-attention** к представлениям энкодера. Естественно подходит для задач sequence-to-sequence — перевода, суммаризации — где весь исходный текст известен заранее.| Архитектура     | Маска                                             | Цель обучения               | Сильные стороны                                | Примеры моделей                      |
| --------------- | ------------------------------------------------- | --------------------------- | ---------------------------------------------- | ------------------------------------ |
| Только энкодер  | нет (двунаправленная)                             | masked-LM (cloze)           | embeddings, классификация, поиск (retrieval)  | BERT, RoBERTa, большинство embedding-моделей |
| Только декодер  | каузальная (`j ≤ i`)                              | предсказание следующего токена | генерация текста, чат, агенты                 | GPT-4, Llama, Claude                 |
| Энкодер–декодер | нет в энкодере, каузальная в декодере (+ cross-attn) | шумоподавление / зашумление спанов | перевод, суммаризация                         | T5, BART, оригинальный трансформер  |

Одно из практических следствий, с которым вы ещё столкнётесь: **embedding-модели**, используемые в модулях 04/05 (`text-embedding-3-small`, `nomic-embed-text`), относятся к энкодерному типу — именно двунаправленный контекст является ключевым для хорошего представления предложения, — в то время как каждая **chat-модель**, вызываемая через `llm_core`, является декодером. В задании 5 эта разница становится наглядной: замените один токен на `⟦PH_0001⟧`, и только двунаправленная модель сможет использовать слово, устраняющее неоднозначность, находящееся _справа_ от маски.

2. Реализуйте `causal_attention(Q, K, V)` / `causalAttention(Q, K, V)` — то же самое, но перед `softmax` постройте и добавьте аддитивную каузальную маску из Задания 1 (`0` для `j ≤ i`, `−∞` для `j > i`).

3. Реализуйте `attention_mass_on_future(weights)` / `attentionMassOnFuture(weights)` — для каждой строки `i` просуммируйте веса строго выше диагонали (`j > i`), затем усредните по строкам. Это измеряет, насколько «правильно» выглядит матрица весов.

4. Реализуйте `nearest_token(repr, E)` / `nearestToken(repr, E)` — argmax косинусного сходства контекстуального представления с таблицей эмбеддингов.

5. Скрипт проверки выполняет **чтение маскированного токена**: каждое предложение имеет вид `the big <sound> today`, где только звук (справа **от** маски) указывает, какое животное скрыто. Он вычисляет представление позиции маски для обоих типов attention и считывает ближайший токен из словаря.

**Критерии приёма:**

- Будущая масса для каузального внимания **строго равна** `0.0`; будущая масса для двунаправленного — `> 0.2`.
- Двунаправленное attention восстанавливает истинный маскированный токен в **≥ 4/5** предложений.
- Каузальное attention восстанавливает **строго меньше** (левый контекст идентичен во всех пяти предложениях, поэтому предсказание не может зависеть от скрытого животного).

# # За рамками этого модуля — современный стек LLM (заметки для собеседований)

Пять улучшений, которые отличают только что созданный вами декодер от production-модели 2024 года и новее.
Это **заметки, а не задачи** — прочитайте их, чтобы названия не застали вас врасплох на собеседовании или в карточке модели (model card).

## # RoPE — rotary positional embeddingsЗадание 2 **добавляло** вектор позиции к каждому эмбеддингу (абсолютные позиции). RoPE (Rotary Positional Embedding) вместо этого **вращает** каждую 2‑D пару измерений query/key на угол, зависящий от позиции: пара `i` в позиции `pos` поворачивается на `θ_i · pos`, где `θ_i = 10000^(−2i/d)` — та же геометрическая шкала частот, что и у ваших синусоид, но применяемая как вращение, а не сложение. Поскольку скалярное произведение двух вращённых векторов зависит только от _разности_ их углов, оценка внимания `q_m · k_n` зависит только от **относительного сдвига** `m − n`, а не от абсолютных позиций — именно это и требуется для языка. RoPE — стандарт в Llama, Qwen и DeepSeek; он позволяет расширять контекстное окно с помощью масштабирования NTK-aware / YaRN: частоты вращения растягиваются так, чтобы предобучённое поведение для относительных позиций охватывало более длинные последовательности.

## # GQA / MQA — grouped-query и multi-query attention

В вашем Задании 1 (MHA) у каждой из `h` голов запроса была своя собственная K‑ и V‑голова — поэтому кэш KV из Задания 4 хранит `h` ключей и `h` значений на токен для каждого слоя. MQA (Multi-Query Attention) сохраняет все `h` голов запроса, но использует **одну** общую K/V‑голову; GQA (Grouped-Query Attention) — это промежуточный вариант — `g` K/V‑голов, каждая из которых общая для `h/g` голов запроса (Llama‑3‑70B: 64 головы запроса, 8 KV‑голов). Объём кэша KV уменьшается ровно в коэффициент разделения (`h/g`, например, в 8 раз). Мотивация заключается в **потреблении памяти и пропускной способности памяти при инференсе, а не в вычислениях (FLOPs)** — во время генерации именно кэш занимает память GPU и данные из него необходимо считывать для каждого нового токена, поэтому его сокращение напрямую позволяет использовать более длинные контексты и большие батчи практически без потери качества.

## # FlashAttention — точное вычисление внимания, учитывающее ввод/вывод (IO-aware)FlashAttention вычисляет **в точности** то же softmax-attention, которое вы реализовали, — это _не_ аппроксимация. Суть в том, что внимание на GPU (графических процессорах) ограничено **пропускной способностью памяти**, а не вычислениями: наивная реализация записывает полную матрицу оценок `n × n` в медленную HBM (High-Bandwidth Memory), считывает её обратно для softmax, записывает веса и снова считывает их для `· V`. FlashAttention разбивает Q, K, V на блоки, которые помещаются в быструю SRAM на кристалле, и объединяет операции `QKᵀ → softmax → · V` в одно ядро (kernel), используя трюк **online softmax** (поддерживая текущий максимум строки и текущий нормализатор по мере потоковой обработки блоков — та же стабилизация `subtract-the-max`, которую вы писали, но вычисляемая инкрементально). Матрица `n × n` никогда не материализуется в HBM; потребление памяти падает с `O(n²)` до `O(n)`, а реальная скорость работы (wall-clock speed) возрастает в несколько раз при больших длинах последовательностей.

## # MoE — FFN со смесью экспертов (mixture-of-experts)

В блоке MoE (Mixture of Experts) одиночный FFN из Задания 3 заменяется на `E` независимых FFN («экспертов») плюс крошечный **роутер**: для каждого токена роутер оценивает всех экспертов и пропускает токен только через **top-k** (обычно `k = 2`), суммируя их выводы с весами вероятностей роутера. Это разделяет **общие** и **активные** параметры — у Mixtral 8×7B всего ≈ 47 B параметров, но на один токен активно только ~13 B — так что вы получаете емкость большой модели при FLOPs (операциях с плавающей точкой) на токен, характерных для маленькой модели. **Вспомогательный лосс балансировки нагрузки** (load-balancing) подталкивает роутер к равномерному распределению токенов по экспертам, иначе он «схлопывается» до нескольких избранных. Обратная сторона: все эксперты всё равно должны находиться в памяти, а маршрутизация усложняет сервинг.

## # Scaling laws — законы масштабирования (Kaplan и Chinchilla)Kaplan et al. (2020) показали, что loss падает по гладким степенным законам (**power laws**) в зависимости от количества параметров `N`, токенов датасета `D` и вычислений `C` (`L ∝ N^−α`, примерно `α ≈ 0.076` для параметров) — это достаточно предсказуемо, чтобы экстраполировать результаты от дешевых прогонов к дорогим. В работе Chinchilla (2022) заново вывели вычислительно-оптимальное распределение и обнаружили, что предыдущие модели были сильно недообучены: при фиксированном бюджете обучения нужно масштабировать `N` и `D` **одновременно**, стремясь к значению **≈ 20 тренировочных токенов на параметр** (Chinchilla: 70 B params × 1.4 T tokens превзошла в 4 раза большую Gopher). Современные модели намеренно «переобучают» (overtrain) далеко за пределами этого соотношения (например, Llama-3-8B видела ~15 T токенов, ≈ 1 900 на параметр), так как оптимум Chinchilla минимизирует вычисления только на этапе _обучения_ — когда **стоимость inference (инференса)** начинает доминировать в жизненном цикле модели, меньшая модель, обученная на гораздо большем количестве токенов, обходится дешевле в обслуживании при равном качестве.
