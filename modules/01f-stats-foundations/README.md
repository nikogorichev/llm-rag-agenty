# # Концепции

## # 1. Теорема Байеса, заблуждение базовой частоты и наивный Байес

Теорема Байеса обращает условную вероятность — она превращает вопрос «какова вероятность этого свидетельства при данной гипотезе» в вопрос «какова вероятность гипотезы при данном свидетельстве»:```
P(H | E) = P(E | H) · P(H) / P(E)
```Классический вопрос на собеседовании: заболеваемость составляет **1%**; тест имеет **95% чувствительность** (P(+ | disease)) и **95% специфичность** (P(− | healthy)). Тест положительный. Какова вероятность, что вы больны? Интуиция подсказывает примерно **95%**. Байес говорит иное. Положительный результат может получиться двумя путями:```
true positive:   prior · sens              = 0.01 · 0.95 = 0.0095
false positive:  (1 − prior) · (1 − spec)  = 0.99 · 0.05 = 0.0495

P(disease | +) = 0.0095 / (0.0095 + 0.0495) ≈ 0.16
```Всего лишь **16%**! Здоровые 99% генерируют в пять раз больше ложноположительных срабатываний, чем больные 1% генерируют истинно положительных. Игнорирование априорной вероятности — это **ошибка игнорирования базовой частоты** (base-rate fallacy) — самая распространённая вероятностная ловушка на собеседованиях (и при чтении метрик ML на несбалансированных данных).

**Наивный байесовский классификатор** превращает этот механизм в классификатор текста. Для документа `w₁…wₙ` и класса `c` формула Байеса даёт `P(c | doc) ∝ P(doc | c) · P(c)`. «Наивный» шаг предполагает, что слова **независимы при заданном классе**, поэтому `P(doc | c) = Π_i P(w_i | c)`. Два практических исправления заставляют это работать:

- **Логарифмическое пространство.** Произведение 50 маленьких вероятностей переполняется до 0. Вместо этого суммируем логарифмы: `log P(c | doc) ∝ log P(c) + Σ_i log P(w_i | c)`.
- **Сглаживание Лапласа (add-one smoothing).** Слово, которое ни разу не встречалось в классе `c`, дало бы `P(w | c) = 0` и заблокировало бы весь класс. Сделаем вид, что каждое слово встречалось на один раз больше, чем на самом деле:```
P(w | c) = (count(w, c) + 1) / (total_tokens(c) + V)        V = vocabulary size
```Prediction — это `argmax_c` от апостериорного логарифма; нормализация апостериорных логарифмов
(стабильный softmax) даёт откалиброванные вероятности классов.

## # 2. Maximum likelihood, и почему ваши функции потерь ЯВЛЯЮТСЯ правдоподобиями

Для независимых одинаково распределённых данных `x₁…x_N` и модели `p(x | θ)`, **правдоподобие** (likelihood) — это
вероятность данных при параметрах θ:```
L(θ) = Π_i p(x_i | θ)         ℓ(θ) = Σ_i log p(x_i | θ)      (log-likelihood)
```**MLE** выбирает такое θ, которое максимизирует `ℓ` — или, что то же самое, минимизирует **negative log-likelihood (NLL)** (отрицательную логарифмическую правдоподобность). Для двух основных рабочих распределений берём производную и приравниваем к нулю:```
Gaussian per-point NLL:   ½·log(2πσ²) + (x − μ)² / (2σ²)
  ∂/∂μ = 0   →  μ̂  = (1/N) Σ x_i               (the sample mean)
  ∂/∂σ² = 0  →  σ̂² = (1/N) Σ (x_i − μ̂)²        (the BIASED variance: ÷N, not N−1)

Bernoulli per-point NLL:  −[ x·log p + (1 − x)·log(1 − p) ]
  ∂/∂p = 0   →  p̂  = (1/N) Σ x_i               (the fraction of 1s)
```А теперь — тот самый вопрос, который любят спрашивать на собеседованиях. Посмотрите на Gaussian NLL как функцию от μ при фиксированном σ: это `MSE/(2σ²) + constant`. Таким образом, **минимизация MSE — это в точности максимизация правдоподобия Гауссиана** — метод наименьших квадратов молчаливо предполагает Гауссов шум. А Bernoulli NLL — это **буквально формула бинарной кросс-энтропии**, член в член — BCE — это не «функция потерь, которая просто работает», это целевая функция MLE для модели, которая выдаёт `P(y = 1)`. (То же рассуждение распространяется на кросс-энтропию с softmax и категориальное правдоподобие — это функция потерь из модуля 08.) В задаче это конкретизируется: перебор по сетке для каждого NLL, перебор по сетке MSE/BCE на тех же данных и наблюдение, как все точки минимума совпадают с аналитическими решениями.

## # 3. Проверка гипотез и A/B-тест

A/B-тест спрашивает: вариант A сконвертировал `conv_a / n_a`, вариант B — `conv_b / n_b` — реальна ли разница или это шум? Сформулируем это как **проверку гипотез**:

- **H₀ (нулевая):** у обоих вариантов одна истинная конверсия; наблюдаемый разрыв — случайность.
- **H₁:** конверсии отличаются.

Выборочная пропорция `p̂` — это среднее нулей и единиц, поэтому по ЦПТ (центральной предельной теореме) она приближённо нормальна с дисперсией `p(1−p)/n`. При H₀ лучшая оценка общей конверсии — **объединённая пропорция**, которая даёт стандартную ошибку разности, а **z-статистика** показывает, сколько стандартных ошибок разрыва мы наблюдаем:```
p̂_pool = (conv_a + conv_b) / (n_a + n_b)
SE      = √( p̂_pool·(1 − p̂_pool)·(1/n_a + 1/n_b) )
z       = (p̂_b − p̂_a) / SE
p-value = 2 · (1 − Φ(|z|))          Φ(z) = ½·(1 + erf(z/√2))
```Значение **p-value** — это `P(a gap this extreme | H₀ is true)` — утверждение о
_данных_, **а не** `P(H₀ is true)`. Если `p < α` (обычно 0.05), мы «отвергаем H₀».
**Доверительный интервал** для реальной разницы использует объединённую SE (каждая
группа сохраняет свою дисперсию): `(p̂_b − p̂_a) ± z_crit·SE_unpooled`. 95%-ный CI,
не включающий 0, согласуется с `p < 0.05`.

Три типа проблем, которые нужно усвоить (в тестовом стенде симулируется каждый):

- **Ошибка первого рода (α):** прогоните A/A-тест (без реальной разницы) много раз,
  и тест всё равно сработает примерно в α случаях. Это не баг — это частота
  ложных срабатываний, которую вы выбрали.
- **Мощность (Power):** при реальном приросте вероятность его обнаружить.
  Растёт с размером выборки и величиной эффекта; тест с недостаточной мощностью
  чаще всего сообщает «нет значимой разницы», даже если эффект есть.
- **Множественная проверка гипотез:** проверьте 20 метрик на A/A-тесте и
  `P(≥1 spurious "win") = 1 − 0.95²⁰ ≈ 64%`. Выберите основную метрику _до_
  эксперимента или скорректируйте множественность (например, Бонферрони: используйте α/20).

## # 4. PCA: направления, максимизирующие дисперсию = собственные векторы ковариационной матрицы

PCA ищет ответ: какие **ортогональные направления** несут больше всего дисперсии?
Центрируйте данные (`X_c = X − mean`), тогда дисперсия проекции на единичный вектор
`v` равна `vᵀ C v`, где `C` — выборочная ковариация:```
C = (1/(N−1)) · X_cᵀ X_c          (D×D, symmetric)
```Максимизация `vᵀ C v` при ограничении `‖v‖ = 1` (с использованием множителя Лагранжа) приводит к `C v = λ v` — оптимум является **собственным вектором** `C`, а дисперсия, которую он объясняет, — его **собственным значением**. Так как `C` симметрична, собственные векторы взаимно ортогональны, поэтому главные компоненты образуют ортонормированный базис, отсортированный по убыванию собственных значений. Доля каждой компоненты в общей дисперсии — это **explained variance ratio** `λ_j / Σ λ`; спроецируйте данные на топ-k столбцов и восстановите для сжатия:```
Z  = X_c @ components[:, :k]            (N×k scores — the compressed data)
X̂  = Z @ components[:, :k]ᵀ + mean      (back to N×D)
```Среднеквадратичная ошибка реконструкции равна отброшенной дисперсии (среднему
отброшенных собственных значений, `Σ_{j>k} λ_j / D`) — значит, она может только
уменьшаться с ростом k, а при k = D реконструкция становится точной (вы просто
повернули и повернули обратно). Датасет задания 10-мерный, но на самом деле
порождён двумя латентными факторами: PCA находит эту плоскость, помещая ≥ 90%
дисперсии в первые 2 компоненты.

Почему это важно дальше в курсе: векторы эмбеддингов (модуль 04) имеют размерность
384, 768, 1536 — с помощью PCA вы их **визуализируете** в 2-D, а также это один из
способов уменьшить размер векторного хранилища. О спектральном разложении: Python
вызывает `np.linalg.eigh` (для симметричных матриц) внутри вашего `pca_fit` —
сортировка полученных пар в порядке убывания — часть задания; в TypeScript есть
готовая `symmetricEigen()` (циклические вращения Якоби), чтобы код на обоих
языках оставался параллельным.

# # Going deeper

- **Introduction to Probability** (Blitzstein & Hwang, Harvard Stat 110) — лучшая
  база по Байесу, распределениям и MLE; бесплатная книга + лекции:
  <https://projects.iq.harvard.edu/stat110>
- **Statistical Inference** (Casella & Berger) — строгий справочник по теории
  правдоподобия и проверке гипотез.
- **StatQuest (Josh Starmer)** — интуитивные видео-объяснения про Байес, MLE,
  p-values и PCA: <https://www.youtube.com/c/joshstarmer>
- **A One-Stop Shop for Principal Component Analysis** — визуальное руководство по
  PCA, собственным векторам и объяснённой дисперсии:
  <https://towardsdatascience.com/a-one-stop-shop-for-principal-component-analysis-5582fb7e0a9c>
- **Evan Miller — How Not To Run an A/B Test** — классическое предостережение о
  подглядывании и множественном тестировании: <https://www.evanmiller.org/how-not-to-run-an-ab-test.html>

# # Environment

Никакого провайдера, сети или LLM — эти упражнения полностью офлайн и детерминированы
(фиксированные seeds, синтетические данные генерируются в коде). Новых переменных окружения нет.

**Python:** только numpy (базовая зависимость — ничего лишнего; `math.erf` из
стандартной библиотеки).```bash
uv run python modules/01f-stats-foundations/py/01_bayes_naive_bayes.py
```**TypeScript:** только обычные массивы (без математических библиотек npm). Ничего не собирай, просто запускай.```bash
pnpm tsx modules/01f-stats-foundations/ts/01-bayes-naive-bayes.ts
```
