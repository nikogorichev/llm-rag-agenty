# Модуль 02 — Интеграция LLM

В модуле 00 вы отправляли одно сообщение и получали ответ.
Здесь вы узнаете, что происходит _вокруг_ этого вызова в реальном приложении:
история переписки, потоковая передача UX (User Experience), учёт затрат,
извлечение структурированных данных, tool calling и написание устойчивого кода для работы с ненадёжными API (Application Programming Interfaces).

В итоге у вас будут рабочие реализации извлечения структурированного вывода
и одного шага (turn) агента с tool calling — два паттерна, которые встречаются почти в каждом
production-решении на LLM (Large Language Model).

# # Концепции

## # Цикл запрос/ответ

Каждый вызов `chat()` является stateless на стороне сервера.
У модели нет памяти между вызовами.
«Память» = вы отправляете полную историю переписки каждый раз.
История — это список сообщений `{role, content}`: `system → user → assistant → user → …`

**Контекстное окно (context window)** — это максимальное суммарное количество токенов (вход + выход), которые модель может обработать за один раз.
Превышение этого лимита приводит к усечению или ошибке — управление этим — ваша ответственность.

## # Потоковая передача (Streaming)

Вместо ожидания полного ответа, потоковая передача возвращает токены по мере их генерации через
Server-Sent Events (SSE). SDK (Software Development Kit) преобразует SSE в Python-итератор / TS-асинхронный итератор.
**Время до первого токена (Time-to-first-token, TTFT)** — это реальная _воспринимаемая_ пользователем задержка;
общее время генерации влияет на пропускную способность, но TTFT влияет на ощущения.

## # Токены и стоимость

LLM работают с _токенами_, а не со словами. Токен — это примерно 3–4 символа английского текста.
`tiktoken` (используется для моделей GPT (Generative Pre-trained Transformer)) позволяет подсчитывать токены на клиенте.
Стоимость = `(input_tokens / 1_000_000) × price_in + (output_tokens / 1_000_000) × price_out`.
Цены отличаются на порядок между моделями — конкретизировать это — цель задания 3.

## # Структурированный вывод

Чтобы попросить модель вернуть JSON (JavaScript Object Notation), требуется:

1. Промт, который описывает точную схему.
2. Парсер (`json.loads` / `JSON.parse`), который обрабатывает markdown-ограждения и другой шум.
3. Валидатор (Pydantic / Zod), который даёт типизированный объект и перехватывает отсутствующие/неверные поля.
4. Цикл повторных попыток или исправлений на случай ошибок парсинга.

Режим JSON (поддерживается в OpenAI и Ollama) гарантирует валидный вывод JSON, но не фиксирует конкретную схему;
ограниченное схемой декодирование (поддерживается некоторыми провайдерами) идёт дальше. Для максимальной переносимости
экстракция через промпт + валидация через Pydantic/Zod работает везде.

## # Tool / function calling — выход за рамки llm_core

Метод `chat()` из `llm_core` оборачивает общее подмножество API всех провайдеров.
Tool calling требует более сложных структур запроса — определений инструментов, `tool_choice`, сообщений с результатами —
которые не ложатся в универсальную обёртку.
Это **сделано намеренно**: здесь абстракция «протекает», чтобы вы поняли, _где_ и почему это происходит.

Цикл инструментов:

```
you → [messages + tool defs] → model
model → [tool_call: name + args JSON]
you → execute the tool locally
you → [messages + tool result] → model
model → [final text answer]
```

OpenAI и Anthropic используют разные форматы передачи данных (разные ключи JSON, разные роли для результатов инструментов),
но логика цикла одинакова.

## # Повторы и ошибки

Вызовы LLM API могут завершаться ошибкой:

- **429 Rate Limit** — делаем паузу и повторяем запрос.
- **500 / 502 / 503 Server Error** — обычно временные; повторяем.
- **401 Unauthorized** — неверный API-ключ; повторение не поможет.
- **400 Bad Request** — некорректный payload; повторение не поможет.

Экспоненциальная выдержка (backoff) с дрожанием: `delay = base × 2^attempt + random(0, base)`.
SDK OpenAI и Anthropic повторяют запросы автоматически (по умолчанию 2 раза) — это упражнение
преподносит паттерн, чтобы вы могли настроить его и применить к любым удалённым вызовам.

## # Task 5 🟢 — Tool / function calling

**Цель:** Реализовать ручной цикл инструментов, используя «сырые» SDK OpenAI и Anthropic.

**Почему не llm_core?** У `llm_core.chat()` нет параметров для определений инструментов или результатов — эти форматы различаются у разных провайдеров. Задача 5 специально опускается на уровень «сырого» SDK.

**Запустить бесплатно / локально (Ollama или LM Studio):** Часть A использует «сырой» протокол OpenAI,
и Ollama, и LM Studio совместимы с OpenAI, поэтому тот же код `openai` SDK будет работать
с ними **без изменений**, достаточно лишь переменных окружения:

| Server    | Env                                               | Default endpoint            |
| --------- | ------------------------------------------------- | --------------------------- |
| LM Studio | `LLM_PROVIDER=lmstudio` (+ `LMSTUDIO_CHAT_MODEL`) | `http://localhost:1234/v1`  |
| Ollama    | `LLM_PROVIDER=ollama` (+ `OLLAMA_CHAT_MODEL`)     | `http://localhost:11434/v1` |

> **Tool calling зависит от _модели_, а не от сервера.** Используйте оптимизированную для инструментов instruct-модель
> (Qwen2.5-Instruct, Llama-3.1/3.2-Instruct, Mistral-Nemo). Маленькие или сильно квантованные модели
> часто пропускают вызов инструмента или возвращают некорректный JSON аргументов. Если `finish_reason`
> выглядит странно у локальной модели, ориентируйтесь на `message.tool_calls?.length`. (LM Studio: загрузите модель,
> затем нажмите **Start Server**, чтобы адрес `:1234` был доступен; Ollama: сначала выполните `ollama pull llama3.2`.)
> **Часть B (Anthropic) использует собственный SDK и протокол — локального аналога здесь нет.**

**Шаги:**

- Выполните инструмент, добавьте сообщение с результатом его работы, снова вызовите API.
- Выведите итоговый ответ.

3. **Часть B (стиль Anthropic):**

- Повторите цикл, используя другой формат SDK `anthropic`.
- Примечание: результаты инструмента для Anthropic помещаются внутрь сообщения `user`, а не на верхний уровень с ролью `tool`.

4. Задайте вопрос, который требует поиска по двум городам — модель должна вызвать инструмент дважды.

**Приемка:**
