# Модуль 06 — Агенты

Агент — это не новый тип модели. Это **цикл**: LLM (Large Language Model) решает, что делать, инструмент запускается, результат возвращается как наблюдение, и LLM принимает решение снова — пока у него не будет достаточно информации, чтобы ответить.

Всё остальное (память, многоагентные системы, фреймворки) — это каркас вокруг этого цикла. В этом модуле мы соберём этот цикл с нуля, чтобы каркас был прозрачен.

---

# # Концепции

## # Что такое агент на самом деле

Уберём хайп. Агент — это:```
loop:
    response = llm.chat(history)           # LLM decides
    if "Final Answer" in response:
        return response                    # done
    tool_result = run_tool(response)       # tool runs
    history.append(tool_result)            # observation feeds back
```Всё. Любой фреймворк агентов (LangGraph, AutoGen, CrewAI) — это предубеждённая (opinionated) реализация этого цикла с добавлением персистентности, маршрутизации и трассировки.

## # ReAct — Reason + Act

ReAct — это паттерн prompting'а, при котором LLM структурирует свой вывод следующим образом:```
Thought: I need to find the height of the Eiffel Tower first.
Action: search
Action Input: eiffel tower height
```Затем вы (цикл агента) запускаете инструмент и внедряете результат:```
Observation: The Eiffel Tower is 330 metres tall.
```И цикл продолжается. Текст модели _и есть_ поток управления. Это работает на любой модели, которая умеет следовать инструкциям — включая локальные модели Ollama. Минус в том, что разбор свободного текста ненадёжен: модель может написать `Action Input:` как `Action input:` или вообще пропустить формат с первой попытки. Вы столкнётесь с этим в Задании 1.

## # Native tool calling — structured vs. parsed

OpenAI и Anthropic добавили встроенную поддержку инструментов в свои API (Application Programming Interfaces). Вместо свободного текста, который нужно парсить, модель возвращает структурированный JSON (JavaScript Object Notation) объект:```json
{ "name": "search", "arguments": { "query": "eiffel tower height" } }
```Более надёжно, но теперь вы привязаны к провайдерам, которые его поддерживают. Абстракция `llm_core` намеренно **не** открывает этот доступ — продвинутые возможности API изучаются на уровне SDK (Software Development Kit), чтобы вы видели реальную структуру каждого провайдера (та же логика, что в модуле 02).

## # Память

LLM не имеют состояния. «Память» нужно реализовывать самостоятельно:

| Вид         | Как                                     | Ограничение                 |
| ----------- | --------------------------------------- | --------------------------- |
| In-context  | добавлять сообщения в список истории    | контекстное окно            |
| Persistent  | чтение/запись файла или БД (Database)   | без ограничений (цена задержки) |
| Summarised  | сжимать старые шаги, чтобы они влезали   | потеря качества при сжатии  |

**Scratchpad** — это компромиссный вариант: агент записывает структурированные заметки (не весь диалог) в файл, а системный промпт добавляет эти заметки в начало каждого шага. Агент «помнит» свои предыдущие выводы, без того чтобы вся история забивала контекстное окно.

## # Агенты на основе фреймворков — LangGraph

LangGraph моделирует агента как **типизированный конечный автомат**:

- **Nodes** (узлы) — это функции Python/JS, которые получают состояние и возвращают обновления.
- **Edges** (рёбра), включая условные рёбра, определяют, какой узел будет запущен следующим.
- **State** (состояние) — это типизированный словарь, который проходит по графу и накапливается.

Стандартный граф агента ReAct выглядит так:```
START -> agent_node
agent_node -> tools_node   (if tool_calls present)
agent_node -> END          (if no tool_calls)
tools_node -> agent_node   (cycle back)
```Фреймворки добавляют контрольные точки (возобновление запуска), стриминг (выдача каждого шага) и трассировку (инспектирование каждого сообщения) с минимальным количеством дополнительного кода. Плата за это — абстракция: когда что-то идёт не так, нужно понимать и ваш код, и внутреннее устройство фреймворка. Построение с нуля сначала (Задача 1) делает отладку прозрачной.

## # Multi-agent

Один контекстное окно имеет пределы. Когда задача слишком сложная или длинная, разделите её:

- **Planner**: декомпозирует вопрос на подзадачи, определяет, какой воркер обрабатывает каждую из них.
- **Workers**: сфокусированные агенты (researcher, calculator, writer), каждый со своим специализированным системным промптом и инструментами.
- **Synthesiser**: объединяет результаты воркеров в связный окончательный ответ.

Воркеры могут выполняться параллельно (каждый получает собственный вызов LLM). Задача планировщика — маршрутизация и декомпозиция, а не выполнение. Этот паттерн повсеместно встречается в продакшене: по сути это map-reduce с LLM.

## # Stop conditions & failure modes — hardening the loop

Цикл в начале этой страницы имеет ровно один выход: модель перестаёт генерировать вызовы инструментов. В продакшенном окружении на это полагаться нельзя. Настоящие циклы агентов проверяют на каждой итерации весь **список критериев выхода**:

- **Terminal message** — модель выдала окончательный ответ вместо вызова инструмента.
- **Goal predicate** — программная проверка того, что цель _действительно_ достигнута (инспектирование состояния мира: файл записан? письмо находится в папке исходящих?).
- **Iteration cap** — жёсткий лимит на число итераций цикла.
- **Wall-clock timeout** — жёсткий лимит на прошедшее время.
- **Unrecoverable error** — сбой инструмента, который не исправить повторными попытками.
- **Stuck detection** — модель зацикливается без прогресса (см. ниже).
- **Explicit exit action** — некоторые окружения предоставляют модели инструмент `finish`/`give_up`, чтобы «я закончил» и «я застрял» были структурированными действиями, а не результатом парсинга текста.Тонкий момент: **терминальное сообщение — это ещё не выполнение цели**. Когда модель прекращает вызывать инструменты и спрашивает: «На какой адрес электронной почты мне это отправить?», цикл завершён — но задача не выполнена. Именно поэтому предикат цели — это _отдельная_ проверка от «больше нет вызовов инструментов»: для успеха требуется и терминальное сообщение, _и_ прохождение предиката; одно лишь терминальное сообщение означает «незавершённость».

Классический **сигнал застревания** — это когда агент вызывает _один и тот же инструмент с теми же аргументами_ N раз подряд — результат ему не понравился, поэтому он спрашивает снова, и так бесконечно. Его «родственник» — это A/B/A/B **осцилляция** между двумя вызовами. Обе ситуации легко детектировать: храните скользящее окно сигнатур `(tool, canonical-args)` и сравнивайте. Прервать выполнение на 5-й итерации при лимите в 10 с диагностикой лучше, чем сжечь оставшийся бюджет на одинаковые вызовы.

И наконец, **идемпотентность** для инструментов с побочными эффектами: повторные попытки неизбежны (сетевые глюки), но повторная попытка `send_email` не должна отправить письмо дважды — и модель, которая повторяет тот же вызов после непонятной ошибки, тоже не должна этого делать. Присвойте каждому _логическому_ вызову стабильный **ключ идемпотентности** (имя инструмента + аргументы, сериализованные в каноническом порядке) и устраняйте дубликаты во время выполнения: если такой ключ уже отрабатывал, верните сохранённый результат вместо повторного запуска инструмента. Обратите внимание: это **инженерия на уровне харнесса, а не модели** — модель не видит этот ключ; цикл гарантирует выполнение побочных эффектов не более одного раза, что бы модель ни делала. (API платёжных систем, например Stripe, предоставляют ровно это через заголовок `Idempotency-Key`.) В задании 6 мы построим всё это, включая инъекцию фейковых часов, чтобы даже ветка с тайм-аутом была детерминистично тестируемой.

- Полный прогон завершается сообщением "All acceptance checks passed."

# # Окружение вокруг цикла (заметки для собеседования)«Учится ли агент в процессе работы?» — частый вопрос на собеседованиях, и ответ требует различать три разных цикла. Первый — **training loop** (обучающий цикл): градиентный спуск на датасете, выполняется **offline** (оффлайн) и выдаёт **frozen weights** (замороженные веса). В этом модуле ничего к этому не прикасается. Когда агент в рамках сессии словно «учится» — вспоминает имя, опирается на прошлые выводы, — это **retrieval from memory** (извлечение из памяти) (черновик из задачи 3, vector stores из модулей 04/05), которое попадает обратно в контекстное окно, а **не обновление весов**. Перезапустите процесс без файла памяти — и «обучение» исчезнет.

Второй — **feedback loop** (цикл обратной связи): сигналы, возвращаемые в систему в разных временных масштабах. На каждой итерации: результаты tools поступают как наблюдения (это и есть агентский цикл). На уровне сессии: правки и оценки пользователя захватываются и анализируются (в модуле 22, задача 4 реализует UX для сбора). На уровне релиза: метрики eval и трейсы продакшена (модуль 21) показывают, действительно ли изменения prompt, корпуса для поиска или fine-tuning датасета улучшили показатели. И здесь во время выполнения веса не меняются — меняются контекст, корпус или следующая тренировка.

Третий — **human loop** (человеческий цикл): пауза с участием человека — это **autonomy boundary** (граница автономии), а не просто UX-удобство. Harness останавливается перед рискованным побочным эффектом (отправка почты, трата денег) и ждёт одобрения — в 06b задача 4 строит это через `interrupt()` из LangGraph, а модуль 22 задача 5 проектирует поток одобрения. Это сочетается с защитами из задачи 6: stop-условия ограничивают то, что агент может делать самостоятельно, а человеческий цикл ограничивает то, что ему разрешено вообще. Вероятное схождение всех трёх — **continual learning** (непрерывное обучение): опыт агента перегоняется в обучающий сигнал, чтобы сегодняшний цикл обратной связи питал завтрашний обучающий цикл; о том, как происходит эта тренировка (post-training и выравнивание), см. модуль 13b.

# # Going deeper- **Статья ReAct**: Yao et al. 2022 — оригинальная статья, где был предложен формат Thought/Action/Observation.
- **Reflexion**: добавляет этап самокритики после каждого действия, чтобы обнаруживать ошибки до того, как они накопятся.
- **Tree of Thought**: ветвит несколько путей рассуждений и выбирает лучший.
- **Человек в контуре** (Human-in-the-loop): добавляет ребро в LangGraph, которое приостанавливает выполнение для утверждения человеком перед запуском инструмента.
- **Оценка агентов** (Agent evals): использовать многошаговые вопросы из Задачи 1 как тестовый набор — измерять, как часто агент приходит к правильному Final Answer за N шагов.
