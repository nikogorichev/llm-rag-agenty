# Модуль 07 — Продвинутый уровень и продакшн

Заставить LLM (Large Language Model) ответить на вопрос — просто. Сложно сделать это **надёжно,
наблюдаемо, дешево и безопасно** — в масштабе, который позволяет вам спокойно спать.
В этом модуле рассматриваются инженерные задачи, отличающие прототип от сервиса для продакшена.

---

# # Концепции

## # Почему evals на первом месте

Невозможно улучшить то, что вы не можете измерить. Прежде чем оптимизировать промпты, менять модели
или добавлять функции, вам нужна базовая линия. Eval-харнесс даёт вам:

- Фиксированный тестовый набор, который не меняется между запусками.
- Оценку для каждого тест-кейса, чтобы понимать, помогло изменение или навредило.
- Сигнал о регрессии: если средний балл падает, значит, что-то сломалось.

**LLM-as-judge** — практическое решение для генерации со свободным ответом. Вместо того чтобы
писать регулярные выражения для текстовых ответов, вы отправляете вопрос, критерии оценки
и ответ модели во _второй_ вызов LLM и просите оценить его от 0 до 10. Это позволяет обработать
нюансы, с которыми не справятся жёстко прописанные проверки. Компромисс: сам судья может
ошибаться, поэтому тщательно проверяйте критерии и валидируйте судью на известных кейсах.

## # Наблюдаемость (Observability)

Каждый вызов LLM в продакшене должен порождать структурную запись:```json
{
  "id": "abc123",
  "timestamp": "2025-01-15T12:00:00Z",
  "provider": "openai",
  "model": "gpt-4o-mini",
  "input_tokens": 142,
  "output_tokens": 38,
  "latency_ms": 412,
  "estimated_cost_usd": 0.000044
}
```JSONL (JSON Lines; newline-delimited JSON) — неплохой начальный формат: одна запись на строку,
удобно для `grep`, легко стримить в data warehouse. В продакшене используйте
**Langfuse** (open-source, self-hostable) или OpenTelemetry для работы с сессиями,
группировкой пользователей, порогами оповещений и дашбордами.

Подсчёт токенов позволяет заранее отловить переполнение контекстного окна и
отследить, какие prompts обходятся дороже всего.

## # Кеширование и управление стоимостью

Inference у LLM — дорого. Кеш, ключ которого — детерминированный хеш от
`(model + messages + options)`, возвращает сохранённый ответ практически бесплатно при
повторных или шаблонных prompts.

Ключевая идея: хеш должен охватывать _всё_, что видит провайдер. Если ваш system
prompt меняется, будет промах кеша — и это правильно. Если он стабилен, вы получаете
бесплатный hit.

**Семантическое кеширование** — следующий шаг: сделайте embeddings входного prompt,
найдите ближайший закешированный prompt выше порога сходства и верните тот ответ.
Это работает с перефразированными повторами. Все нужные инструменты появятся
после модуля 04.

## # Ограждение (guardrails) и безопасность

Ограждения должны быть с обеих сторон вызова LLM:

**Входные ограничения:**

- Пустой или слишком длинный ввод — отвергайте сразу, не тратьте токены.
- Prompt injection — фразы вроде "ignore previous instructions" сигнал о том,
  что пользователь пытается переопределить ваш system prompt.
- Очистка PII (Personally Identifiable Information) — адреса почты, телефоны, SSN
  не должны покидать вашу систему в сторону стороннего API (Application Programming Interface)
  без согласия.

**Выходные ограничения:**

- Детекция отказа — "I cannot help with that" допустимый ответ, но ваш UI (User Interface)
  должен обработать его корректно, а не показывать ошибку.
- Валидация схемы — если вы ожидаете JSON, распарсите его и ошибайтесь раньше,
  если это не так.
- Очистка эха PII — модели иногда дословно повторяют ввод пользователя; очищайте
  и выход.

## # Serving (Обслуживание)

HTTP (HyperText Transfer Protocol) сервер — последний элемент. Простейший путь в продакшен:- **Python**: FastAPI + Uvicorn. Асинхронная поддержка FastAPI естественным образом сопоставляется с асинхронными вызовами LLM и стриминговыми ответами.
- **TypeScript**: встроенный в Node.js модуль `http` (для базовых задач фреймворк не нужен) или Express для маршрутизации и middleware.

Два паттерна для эндпоинтов:

1. **Синхронный** (`POST /chat`): дождаться полного ответа, вернуть JSON. Просто для клиентов; выше воспринимаемая задержка.
2. **Стриминговый** (`POST /chat/stream`): возвращать токены по мере генерации через chunked transfer или Server-Sent Events (SSE). Ниже воспринимаемая задержка ценой небольшого усложнения клиентского кода.

# # Углубляемся

- **Langfuse**: платформа observability (наблюдаемости) для LLM с открытым исходным кодом, поддерживающая трассировку сессий, группировку пользователей и дашборд скоринга. Drop-in замена для JSONL-логгера — вы реализуете её в **Task 6**. Документация: <https://langfuse.com/docs> (справочник по SDK:
  <https://langfuse.com/docs/sdk/python> / <https://langfuse.com/docs/sdk/typescript>).
- **OpenTelemetry**: индустриальный стандарт распределённой трассировки — полезен, когда ваш LLM-сервис — один из узлов в большей графе микросервисов.
- **Семантическое кэширование (semantic caching)**: получить эмбеддинги входящих промптов и найти ближайшие закэшированные эмбеддинги выше порога. Обрабатывает перефразированные повторы, которые пропускают кэши на основе точного хэша.
- **Структурированные выходы (structured outputs)**: `response_format: { type: "json_schema" }` у OpenAI и режим tool-use у Anthropic гарантируют валидный JSON на выходе — надёжнее, чем валидация post factum.
- **Red-teaming**: систематическое adversary-тестирование для поиска обходов защитных механизмов. Можно автоматизировать: запустить LLM-"атакующую", которая генерирует попытки инъекций против защищённого пайплайна, и измерить долю заблокированных.
