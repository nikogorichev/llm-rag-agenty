# # Концепции

## # Что такое классификация?

Классификация отображает входной объект на одну из _C_ дискретных меток. Для текста это вопросы типа
«это спам?», «какая тема у статьи?» или «отзыв положительный?».
Сложная часть — представление: как превратить слова в то, из чего математическая модель сможет учиться?

## # Три подхода (и когда какой использовать)

| Подход                    | Как работает                                                                            | Требуются размеченные данные?            | Стоимость inference          |
| ------------------------- | --------------------------------------------------------------------------------------- | ---------------------------------------- | ---------------------------- |
| LLM zero/few-shot         | Промпт модели с набором меток; позволить ей «понять»                                   | Нет (few-shot требует примеров, не меток) | Высокая — один LLM-вызов на элемент |
| Embeddings + обученная головка | Embed текста → вектор float → обучить LR (Logistic Regression) или kNN (k-Nearest Neighbors) | Да — ~20+ на класс                      | Низкая — только скалярные произведения      |
| С нуля                    | Embed текста → обучить softmax LR градиентным спуском                                     | Да                                      | Низкая                          |

Ключевая идея: **embeddings разделяют «понимание текста» и «принятие решения»**.
Embedding-модель выполняет основную семантическую работу на этапе получения embed-данных. В режиме inference
классификатору нужно лишь найти разделяющую поверхность в уже построенном векторном пространстве —
что стоит недорого.### Softmax и перекрёстная энтропия (математика, задание 4)

Логистическая регрессия для нескольких классов работает так:

**Softmax** превращает вектор «сырых» оценок (логитов) в распределение вероятностей:```
softmax(z)_j = exp(z_j) / Σ_k exp(z_k)
```Каждое значение выхода лежит в диапазоне (0, 1) и их сумма равна 1 — корректное распределение вероятностей.
Перед вычислением exp() вычтите максимум в строке, чтобы избежать числового переполнения (это не изменит результат).

**Функция потерь перекрёстной энтропии** (cross-entropy loss) показывает, насколько вероятности ошибочны:```
L = -1/N * Σ_i log( p[i, y[i]] )
````p[i, y[i]]` — предсказанная вероятность для ИСТИННОГО класса примера i.
Если значение 1.0 (идеально), log(1) = 0 — потери нет. Если 0.01 (очень неверно), log(0.01) ≈ −4.6 — большой штраф.

**Градиент** (красивый результат — вывод см. в Karpathy micrograd):```
dL/dz = p - one_hot(y)
```Вот и всё. Градиент в каждой позиции — это просто (предсказанная вероятность) минус (истинная вероятность).
Это естественно получается при совместном дифференцировании softmax и перекрёстной энтропии.

Отсюда:```
dL/dW = Xᵀ @ dL/dz / N
dL/db = mean(dL/dz, axis=0)
```**Почему для F1 используется среднее гармоническое (F1 score — гармоническое среднее точности и полноты)?**

Арифметическое среднее точности и полноты может вводить в заблуждение: классификатор с precision=1.0 и recall=0.0 получил бы арифметический балл 0.5, но бесполезен (он никогда ничего не предсказывает). Гармоническое среднее наказывает крайние значения:```
F1 = 2 * P * R / (P + R)
```P=1.0, R=0.0 → F1 = 0. Это правильный ответ.

## # Дисбаланс классов, калибровка и PR против ROC (заметки к собеседованию)

Три практических вопроса по ML, которые возникают почти на каждом собеседовании и в которых легко ошибиться:

**Дисбаланс классов.** При распределении 99:1 стратегия «всегда предсказывать мажоритарный класс» даёт точность 99% — именно поэтому точность здесь неподходящая метрика (используйте precision/recall/F1 по классам, именно это строится в Задании 3). Способы исправления, в порядке их применения:

1. **Ничего не делайте с данными, исправьте метрику и порог** — оценивайте по F1 или PR-AUC и сдвигайте порог принятия решения вместо переобучения.
2. **Веса классов** — масштабируйте член потерь каждого класса на `N / (K · N_class)`, чтобы редкие классы вносили равный вклад в градиент (одна строка в cross-entropy).
3. **Ресемплирование** — oversample меньшинства (дублирование или синтез, например SMOTE интерполирует между соседями меньшинства) или undersample большинства. Ресемплируйте **только обучающую выборку** — ресемплирование до разделения приведёт к утечке дублированных строк в тестовую выборку.

**Калибровка.** Классификатор _калиброван_, когда его оценки являются вероятностями: среди примеров с оценкой `p = 0.8` примерно 80% действительно положительные. Современные нейросети обычно **избыточно уверены**; проверьте это диаграммой надёжности (разбиение по предсказанной вероятности, график точности бина против уверенности бина) и исправьте постфактум с помощью **Platt scaling** (обучите логистическую регрессию на отложенных оценках) или **temperature scaling** (поделите логиты на один обучаемый `T > 1` перед softmax — то же `T` из сэмплера модуля 01). Калибровка важна везде, где вероятность управляет решением — маршрутизация малоуверенных выводов на человеческую проверку (модуль 21, Задание 4) работает только если «уверенность 0.6» действительно означает 0.6.**Кривая PR против ROC.** ROC (модуль 01b) строит график TPR относительно FPR; кривая precision–recall (точность-полнота) строит график точности относительно полноты. При сильном дисбалансе ROC-AUC может выглядеть отлично, хотя классификатор бесполезен, потому что FPR делится на огромное количество отрицательных примеров и почти не меняется; точность делится на _положительные предсказания_ модели, поэтому она падает, когда ложноположительные результаты затапливают редкие положительные. Правило: сбалансированные классы или симметричные затраты → ROC; редкий положительный класс, где ложные срабатывания критичны (мошенничество, детекция инъекций в модуле 20) → PR-кривая и PR-AUC.

## # Задание 4 🔴 — Классификатор с нуля

**Цель:** Реализовать мультиномиальную логистическую регрессию с градиентным спуском, используя только numpy (Python) / обычные массивы (TypeScript).

**Файлы:**

- `py/04_logistic_scratch.py`
- `ts/04-logistic-scratch.ts`

**Шаги:**

Загрузка данных, разбиение на train/test и тренировочный цикл уже реализованы. Вам нужно реализовать:

1. `softmax(z)` — построчно вычисленный численно устойчивый softmax:```python
   z_stable = z - z.max(axis=1, keepdims=True)
   exp_z = np.exp(z_stable)
   return exp_z / exp_z.sum(axis=1, keepdims=True)
   ```2. `cross_entropy_loss(probs, y)` — обрезать probs на уровне 1e-12, собрать `probs[i, y[i]]`,
   вернуть `-mean(log(correct_probs))`.

3. `forward(X)` — `Z = X @ W + b`, затем `softmax(Z)`.

4. `gradient_step(X, y)` — основа задачи:```
   probs = forward(X)
   loss  = cross_entropy_loss(probs, y)
   dZ    = probs - one_hot(y)       # the elegant gradient
   dW    = X.T @ dZ / N
   db    = mean(dZ, axis=0)
   W    -= lr * dW
   b    -= lr * db
   return loss
   ```**Критерии приёмки:**

- Loss монотонно убывает на первых 50 эпохах.
- Точность (accuracy) на тесте после 300 эпох составляет ≥ 50% (благодаря embedding-признакам это достижимо).
- `softmax([[1, 2, 3]])`) даёт в сумме примерно 1.0 для каждой строки.
- В коде модели и вычисления градиентов не использован sklearn или сторонние ML-библиотеки.

**«Красивый» градиент:** Градиент softmax cross-entropy по отношению к pre-softmax логитам равен просто `p - one_hot(y)`. Там, где модель уверена и ошибается, градиент велик; где уверена и права — он стремится к нулю. Именно этот элегантный результат делает комбинацию softmax + cross-entropy универсальным стандартом для задач классификации.

# # Какой подход использовать когда| Ситуация                                               | Рекомендуемый подход                                  |
| ------------------------------------------------------- | ----------------------------------------------------- |
| Нет размеченных данных, гибкие или изменяемые метки     | LLM zero-shot                                         |
| Несколько примеров на класс (< 10)                      | LLM few-shot                                          |
| 20–100+ размеченных примеров на класс, фиксированный набор меток | Embeddings + обучаемая голова (LR или kNN)             |
| Нужна задержка в пределах субмиллисекунд или очень высокая пропускная способность | Embeddings + обучаемая голова                         |
| Сбор меток дорог, но есть чат-модель                    | LLM few-shot как разметчик-оракул, затем обучить голову |
| Нужно понять, как модель на самом деле работает         | С нуля (Task 4)                                        |
| Модель с миллиардами параметров, много вариаций задач   | Fine-tune (за рамками этого модуля)                    |

**Эмпирическое правило:** LLM zero/few-shot — правильная стартовая точка: данные не требуются, а точность часто удивительно высокая. Если есть размеченные данные и нужен дешёвый inference, обучите голову на эмбеддингах. Задача «с нуля» не для продакшена; она нужна для интуиции.
