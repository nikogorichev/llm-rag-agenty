# Модуль 13b — Пост-обучение и выравнивание (RLHF и DPO)

> **Теги глубины** 🟢 app-level · 🟡 build-one-piece-by-hand · 🔴 from-scratch

«Как на самом деле обучают ChatGPT?» — один из самых популярных вопросов на собеседованиях по LLM (Large Language Model), а полный ответ состоит из трёх этапов: **pretraining** → **SFT (Supervised Fine-Tuning)** → **preference optimization** (RLHF (Reinforcement Learning from Human Feedback) или DPO (Direct Preference Optimization)). Модуль 13 охватывает средний этап (SFT + LoRA) и на этом завершается. Этот сопутствующий материал с нуля реализует недостающий третий этап на игрушечных моделях: данные предпочтений → reward model → RLHF (и его знаменитый режим отказа — reward hacking) → DPO.

Здесь всё — **чистый numpy (Python) / plain TypeScript (без математических библиотек)**, полностью **offline** и **детерминированно** (фиксированные seed'ы, синтетические данные, генерируемые в коде). Никаких провайдеров, сети или LLM — «ответы» — это синтетические признаковые векторы, а политики — небольшие табличные softmax'ы, что делает каждый алгоритм полностью наглядным. Вы реализуете ключевые с учебной точки зрения функции; игрушечные миры, циклы обучения и отчёты уже предоставлены и становятся runnable, как только вы заполните заглушки.

**Общая игрушечная схема** (используется во всех задачах): небольшой набор «prompts», у каждого есть K кандидатов-«responses», представленных в виде признаковых векторов `x ∈ ℝ^D`; скрытая истинная награда `r*(x) = w*·x`, которая играет роль реальных человеческих предпочтений; и референсная политика `π_ref` (почти равномерный softmax по кандидатам) в качестве замены модели SFT. Метки предпочтений сэмплируются из истинной награды с реалистичным шумом, и каждый эксперимент задаёт вопрос: **какую часть `r*` мы можем восстановить — и что происходит, когда мы оптимизируем по несовершенной копии?**

# # Concepts

## # 1. Конвейер пост-обучения, данные предпочтений и Elo

Что каждый этап обучения даёт модели:| Этап                       | Данные                                | Что приобретает модель                                      |
| --------------------------- | ----------------------------------- | --------------------------------------------------------- |
| **Предобучение** (Pretraining)             | Сырой текст веб-масштаба                  | Язык, факты, способность к рассуждениям — предсказание следующего токена |
| **SFT** (модуль 13)         | Демо `(prompt, good response)`     | Следует инструкциям, отвечает в формате ассистента     |
| **Оптимизация предпочтений** | Пары `(prompt, chosen ≻ rejected)` | Полезный/безопасный _суждение_ — выбирает лучшее поведение  |

Почему третий этап использует **попарные сравнения** вместо оценок по шкале?
Потому что люди ненадежны в абсолютных оценках («это 7 из 10?»), но
последовательны в относительных («A лучше, чем B»). Попарные предпочтения —
исходный материал для выравнивания (alignment) — и для лидерборда Chatbot Arena, который
буквально состоит из миллионов голосов «какой ответ лучше?».

Два классических способа агрегировать множество попарных исходов:

- **Матрица винрейта** (win-rate matrix): `W[a][b]` = доля матчей, в которых `a` победил `b`.
  Просто, интерпретируемо и уже достаточно для упорядочивания моделей.
- **Рейтинги Эло** (Elo ratings) (из шахмат, используются Chatbot Arena): у каждого игрока есть рейтинг `R`; перед матчем ожидаемый счём A равен```
  E_A = 1 / (1 + 10^((R_B - R_A) / 400))
  ```и после наблюдения реальной оценки `S_A ∈ {0, 1}` оба рейтинга обновляются:```
  R_A ← R_A + k · (S_A - E_A)          (and symmetrically for B)
  ```Неожиданные победы (низкое `E_A`, фактическое значение 1) сильно сдвигают рейтинги; ожидаемые победы почти не меняют их. Если полностью переиграть лог матча, рейтинги сойдутся так, чтобы разрывы между ними воспроизводили наблюдаемые вероятности побед.

## # 2. Модель Брэдли–Терри и моделирование вознаграждения

Чтобы _оптимизировать_ на основе предпочтений, нам нужен скалярный сигнал, поэтому мы обучаем **модель вознаграждения** `r_θ(x)` на парах предпочтений. Связь между скалярными вознаграждениями и попарными исходами задаёт **модель Брэдли–Терри**:```
P(a ≻ b) = σ(r(a) − r(b)) ,      σ(z) = 1 / (1 + e^{-z})
```т. е. вероятность того, что `a` будет выбрана, растёт с увеличением разницы вознаграждений. (Elo — это та же модель в десятичной системе счисления со шкалой в 400 баллов.) Обучение reward model тогда сводится просто к максимизации правдоподобия на наблюдаемых парах — к функции потерь, которую использовал InstructGPT:```
L(θ) = −E_pairs [ log σ( r_θ(x_chosen) − r_θ(x_rejected) ) ]
```Для нашей линейной модели вознаграждения `r_θ(x) = θ·x` градиент имеет следующий вид (вывод: `d/dΔ[−log σ(Δ)] = −(1−σ(Δ))`, затем применяем цепное правило к `Δ = θ·x_c − θ·x_r`):```
∂L/∂θ = −E_pairs [ (1 − σ(Δ)) · (x_chosen − x_rejected) ]
```Обратите внимание на форму этого градиента: пары, которые модель уже ранжирует уверенно
(`σ(Δ) ≈ 1`), вносят нулевой вклад; пары, с которыми она ошибается, подтягивают `θ`
в сторону признаков выбранного ответа. При достаточном количестве (шумных!) пар `θ`
восстанавливает _направление_ истинной награды `w*` — задача 2 проверяет это через косинусное сходство.
Масштаб не определяется (Bradley–Terry «видит» только разности), так же не определяется
и постоянное смещение — помните этот момент «с точностью до аффинного преобразования»;
именно этот зазор и использует DPO.

## # 3. RLHF: максимизация награды с KL-ограничением — и reward hacking

Имея наградную модель, RLHF настраивает политику так, чтобы максимизировать её — но не вслепую.
Целевая функция выглядит так:```
maximize_π   E_π [ r(x) ]  −  β · KL(π ‖ π_ref)
```где `KL(π ‖ π_ref) = Σ_k π(k)·log(π(k)/π_ref(k))` измеряет, насколько политика отклонилась от референсной (SFT) модели. **KL‑член — это поводок.** Он нужен, потому что `r` — не истина, это _прокси_, обученный на конечных зашумлённых данных, и он надёжен лишь вблизи того распределения, на котором обучался. Уйдя далеко от `π_ref`, вы попадаете в область, где reward модель ошибается с большой уверенностью.

Продуктивные системы оптимизируют этот объект с помощью **PPO (Proximal Policy Optimization)** — усечённых обновлений, value‑сетей, работы с минибатчами. Всё это — инженерные приёмы снижения дисперсии вокруг одной и той же базовой идеи, а именно обычного **REINFORCE (градиента политики)**, нашего «заменителя». Для табличной политики `π = softmax(z)` точный градиент ожидаемого награждения:```
∂/∂z_j  E_π[R]  =  π(j) · (R(j) − b) ,      baseline b = Σ_k π(k)·R(k)
```(базлайн не меняет ожидание, он просто центрирует сигнал —
«REINFORCE with a baseline»). А KL-штраф сворачивается в **формирование
награды** (reward shaping): оптимизация `E_π[R] − β·KL` — это _точно_ REINFORCE на
модифицированной награде `R'(k) = R(k) − β·log(π(k)/π_ref(k))`.

**Reward hacking / закон Гудхарта** («когда мера становится целью, она
перестает быть хорошей мерой») — это то, что демонстрирует Задача 3. Модель
награды переоценивает один «эксплойтский» ответ, чья истинная награда ужасна.
Оптимизируй прокси без KL-штрафа, и получаешь классическую **кривую
переоптимизации**: истинная награда сначала _растёт_ (прокси в основном прав,
поэтому прогресс реальный), а затем _обрушивается_, когда политика концентрирует
всю свою массу на эксплойте, — в то время как прокси-награда выглядит лучше,
чем когда-либо. Добавь KL-штраф, и политика остановится в «доверенной зоне»:
истинная награда остаётся вблизи пика, а эксплойт остаётся редким. Именно поэтому
в каждой статье по RLHF строят график истинной награды против прокси, и почему
важен параметр β.

## # 4. DPO: ваша языковая модель — это тайная модель награды

DPO сворачивает весь конвейер RLHF (модель награды + RL-цикл) в одну функцию
потерь для обучения с учителем. Вывод состоит из трёх шагов — выучите их, это
жемчужина на собеседованиях:

**Шаг 1.** Приведённая выше KL-регуляризованная целевая функция имеет
**оптимальную политику в замкнутом виде** (напишите лагранжиан или просто
проверьте, что условие стационарности выполняется):```
π*(y)  ∝  π_ref(y) · exp( r(y) / β )
```Интуиция: пересчитать веса эталонной политики с помощью экспоненты от вознаграждения, где β определяет, насколько сильным будет этот наклон.

**Шаг 2.** Инвертировать выражение, чтобы представить вознаграждение через политику:```
r(y)  =  β · log( π*(y) / π_ref(y) )  +  const
```(константа — это лог-нормализатор, она зависит от промпта, но не от `y`).

**Шаг 3.** Подставим в модель Bradley–Terry для пары `(y_w выбран, y_l отвергнут)` — константа **сокращается** в разности — и получаем функцию потерь без явной reward model:```
m  =  β·[ (log π_θ(y_w) − log π_ref(y_w)) − (log π_θ(y_l) − log π_ref(y_l)) ]
L  =  −log σ(m)
```Обучайте стратегию прямо на предпочтениях с этой функцией потерь, и она _неявно_
становится собственной моделью вознаграждения — величина `β·log(π_θ(y)/π_ref(y))`
называется **implicit reward**, а в задании 4 можно наблюдать, как растёт её отрыв
(разрыв) в процессе обучения. Никакого семплирования, цикла RL и отдельной модели
вознаграждения; β по-прежнему выполняет роль KL-поводка, так как loss даёт эффект
только при перемещении _относительно_ `π_ref`.

**Варианты, которые нужно уметь называть:** **RLAIF / Constitutional AI**
(Anthropic) — метки предпочтений поступают от AI-судьи, применяющего записанную
конституцию, вместо человеческих аннотаторов; **KTO** — работает с независимыми
метками «хорошо/плохо» (пары не нужны), используя loss в стиле теории перспектив;
**IPO** — заменяет `−log σ` у DPO на квадратичный loss по отрыву, чтобы избежать
переобучения на уверенных парах; **GRPO** (DeepSeek-R1) — упрощение PPO,
которое отбрасывает value-сеть и нормализует вознаграждения внутри группы
семплированных ответов для каждого промпта (рабочая лошадка RL для reasoning-моделей).

# # Углубляемся

- **Статья InstructGPT** (Ouyang et al., 2022) — рецепт SFT → RM → PPO, ставший
      основой ChatGPT; функция потерь reward-модели из задания 2 — это уравнение 1:
      <https://arxiv.org/abs/2203.02155>
- **Статья DPO** (Rafailov et al., 2023) — "Your Language Model is Secretly a
      Reward Model"; раздел 4 содержит набросок вывода, упомянутый в Concepts §4:
      <https://arxiv.org/abs/2305.18290>
- **Constitutional AI** (Bai et al., 2022) — RLAIF: замена человеческих меток
      предпочтений на обратную связь от ИИ, направляемую конституцией:
      <https://arxiv.org/abs/2212.08073>
- **Блог Hugging Face про RLHF + документация TRL** — как продакшен-стек
      реализует всё это (PPOTrainer, DPOTrainer, reward modeling):
      <https://huggingface.co/blog/rlhf> и <https://huggingface.co/docs/trl>
- **Scaling laws for reward model overoptimization** (Gao et al., 2022) —
      реальная версия кривой Гудхарта из задания 3:
      <https://arxiv.org/abs/2210.10760>
- **DeepSeek-R1 / GRPO** (2024–25) — group-relative policy optimization,
      упрощение PPO, стоящее за волной моделей рассуждения:
      <https://arxiv.org/abs/2402.03300>
