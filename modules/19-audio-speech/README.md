# # Концепции

## # Аудиальная модальность

Аудио — это одномерный временной ряд: последовательность замеров давления, взятых с фиксированной частотой (обычно 16 000 замеров в секунду для речи, 44 100 для музыки). Двухсекундная запись при 16 кГц — это 32 000 целых чисел — значительно меньше, чем HD-изображение, но достаточно много, чтобы отправка полного потока в LLM требовала чанкования, стриминга или офлайн-батчинга.```
microphone → ADC → PCM samples (int16) → WAV file / streaming buffer
```Все модели ASR и TTS в конечном итоге потребляют или создают этот поток исходных сэмплов.
Контейнер `.wav` — это просто заголовок (44 байта), за которым следует сырой PCM (импульсно-кодовая модуляция); вы можете
просматривать и генерировать его, используя только стандартные библиотеки Python или Node.js (задачи 1
и 4 демонстрируют это).

## # Speech-to-text (STT / ASR)

Automatic speech recognition сопоставляет звуковую волну с текстовой транскрипцией.
Доминирующая архитектура — это **encoder–decoder transformer**: энкодер
преобразует кадры мел-спектрограммы в контекстные представления, а декодер
авторегрессионно генерирует последовательность токенов word-piece.

**OpenAI Whisper** (2022) — эталонная open-source ASR-модель, обученная на
680 000 часах многоязычного аудио из интернета. Она доступна:

- **Hosted** через `client.audio.transcriptions.create()` (whisper-1, ~$0.006/min)
- **Local** через `faster-whisper` — переimplementation на CTranslate2, которая работает
в 4–8 раз быстрее исходной PyTorch-модели на CPU.

**Groq** также предоставляет hosted-эндпоинт Whisper с очень низкой задержкой, если у вас есть
Groq API key (библиотека `groq`, та же форма OpenAI-совместимого эндпоинта).

## # Text-to-speech (TTS)

TTS инвертирует процесс ASR: по текстовой строке синтезируется звучащая естественно
речевая волна. Современные нейронные TTS-модели (WaveNet → Tacotron → FastSpeech 2 →
на основе диффузии) следуют одному и тому же высокоуровневому шаблону:```
text → phonemes → mel-spectrogram → vocoder → PCM waveform
```**OpenAI TTS** (`client.audio.speech.create()`) предлагает шесть голосов (alloy, echo,
fable, onyx, nova, shimmer) и две модели:

| Model    | Качество | Задержка | Стоимость        |
| -------- | ------- | ------- | ----------- |
| tts-1    | хорошее    | быстрая    | $15/M chars |
| tts-1-hd | лучше  | медленнее  | $30/M chars |

Тело ответа — это бинарный аудиопоток, который можно сохранить напрямую на диск как
`.mp3` (или `.wav`, `.opus` и т. д.).

## # Конвейер голосового агента (пакетный)

Простейший цикл голосового взаимодействия:```
mic audio → Whisper API → transcript
              ↓
          LLM + RAG → answer text
              ↓
          TTS API → speech → speaker
```**Бюджет задержки** (приблизительные цифры для хостинг-провайдеров API):

- Транскрипция Whisper: 1–3 с для 5-секундного фрагмента
- Ответ LLM (gpt-4o-mini): 1–4 с
- Синтез TTS: 1–2 с для короткого предложения
- Итого: **3–9 с** в оба конца

Это приемлемо для асинхронных голосовых заметок, но слишком медленно для естественного разговора. Realtime API (задание 5) решает эту проблему.

## # Предобработка аудио: почему это важно

Модели ASR обучаются на относительно чистой речи. Реальные записи содержат:

- **Фоновый шум**: гул вентилятора, системы вентиляции, уличный шум
- **Артефакты кодека**: сжатие MP3 с низким битрейтом
- **Тишину в начале**: несколько секунд тишины до начала речи
- **Перекрывающуюся речь**: несколько говорящих одновременно

Даже простая предобработка значительно снижает коэффициент ошибок в словах (WER):

| Этап предобработки                     | Типичное снижение WER                          |
| -------------------------------------- | ---------------------------------------------- |
| Обрезка тишины (VAD)                   | 5–10% (более быстрый inference, меньше галлюцинаций) |
| Шумоподавление (спектральное вычитание) | 10–25% в шумных условиях                     |
| Диаризация говорящих                    | Позволяет транскрибировать каждого говорящего по отдельности |

**Voice Activity Detection (VAD)**: задача определения, какие кадры содержат речь, а какие — тишину. В задании 4 реализован базовый метод на основе энергии: аудио разбивается на кадры по 30 мс, вычисляется энергия RMS (Root Mean Square) для каждого кадра, кадры выше порога помечаются как «речь». Это самый простой подход, и он работает на удивление хорошо для студийных записей.

Более продвинутый VAD: **WebRTC VAD** (Google, C-библиотека, Python-биндинги через `webrtcvad`) использует смесь Гауссовых моделей; **Silero VAD** — крошечная модель на основе LSTM (Long Short-Term Memory), которая работает в реальном времени на CPU.

**Шумоподавление**: пакет `noisereduce` (Python) реализует спектральное вычитание — он оценивает спектр шума по тихому сегменту и вычитает его из спектра сигнала кадр за кадром. Хорошо подходит для стационарного шума (вентилятор, шипение), менее эффективен для нестационарного (речь, музыка).**Диаризация говорящих**: «кто говорил когда?» — сегментирует аудио по голосам
говорящих без предварительного знания о том, кто это. Каноническая библиотека
с открытым кодом — `pyannote.audio` (требует токен HuggingFace). Варианты
в виде хостинга — AssemblyAI или Deepgram.

## # Архитектура голосового взаимодействия в реальном времени

OpenAI **Realtime API** заменяет трёхэтапный пакетный конвейер одним
постоянным WebSocket:```
audio stream ──► WebSocket ──► GPT-4o-realtime ──► audio stream
                    (STT + LLM + TTS in one step, streaming)
```Модель начинает говорить до того, как завершила генерацию полного текста
(потоковая генерация текстовых токенов управляет параллельным синтезом аудио). Первый байт аудио поступает через **300–500 мс** по сравнению с 3–9 с при пакетной обработке.

Компромиссы по сравнению с пакетной обработкой:

|             | Batch (tasks 1–3)                       | Realtime (task 5)                       |
| ----------- | --------------------------------------- | --------------------------------------- |
| Latency     | 3–9 s                                   | 300–500 ms                              |
| Cost        | Оплата за STT + LLM + TTS               | Более высокая поминутная ставка         |
| Control     | Полный: внедрять RAG-контекст, фильтровать вывод | Ограниченный: модель обрабатывает всё сама |
| Reliability | Каждый шаг повторяется независимо       | Единичный сбой WebSocket = полный перезапуск |
| Use case    | Голосовые заметки, асинхронные запросы  | Голосовые разговорные агенты            |

# # Going deeper

## # Local ASR models

- **faster-whisper** — порт Whisper на CTranslate2; в 4–8 раз быстрее на CPU с
  int8-квантованием. Модель `tiny` занимает 75 МБ и работает в реальном времени на MacBook Pro 2019 года.
  [github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper)
- **whisper.cpp** — порт на C++; работает на GPU Apple Silicon Metal.
  [github.com/ggerganov/whisper.cpp](https://github.com/ggerganov/whisper.cpp)
- **Parakeet / Canary** (NVIDIA NeMo) — SOTA (State-of-the-Art) открытые ASR-модели для английского языка с
  WER, приближающимся к человеческому уровню на чистой речи.

## # Groq Whisper endpoint

Groq размещает Whisper с очень низкой задержкой (часто менее 300 мс для короткого фрагмента).
Endpoint совместим с OpenAI; достаточно изменить `base_url`:```python
import groq
client = groq.Groq()
result = client.audio.transcriptions.create(
    model="whisper-large-v3-turbo", file=audio_file
)
```### Диаризация

- **pyannote.audio** — стандартный конвейер с открытым исходным кодом; требует токен HuggingFace для модели с ограниченным доступом.
  [huggingface.co/pyannote/speaker-diarization-3.1](https://huggingface.co/pyannote/speaker-diarization-3.1)
- **AssemblyAI** / **Deepgram** — хостинговая диаризация через REST (Representational State Transfer) API.

## # Альтернативные нейронные TTS

- **Coqui TTS** — с открытым исходным кодом, множество голосов, локальный инференс.
- **ElevenLabs** — клонирование голоса высочайшего качества; REST API.
- **Bark** (Suno) — выразительный TTS, включая смех и неречевые звуки.

## # Стриминг аудио из браузеров

В продакшн голосовых агентах браузер стримит аудио напрямую в ваш бэкенд через **WebRTC** или **WebSocket**. Бэкенд передаёт чанки в STT API и стримит TTS-аудио обратно. Библиотеки:
