# Модуль 23 — Финальный проект

У вас есть все строительные блоки. Теперь пора собрать их воедино.

Финальный проект — это задача с открытой постановкой. Никаких заготовок, которые нужно заполнить, никаких отмеченных TODO — только техническое задание, план этапов и честные критерии оценки. Цель — выпустить что-то, чем вы действительно хотели бы пользоваться, и проследить, чтобы каждое проектное решение опиралось на пройденный материал.

Сначала изучите `projects/news-agent`. Это полный пример end-to-end, который объединяет модули 02, 04, 05 и 06 в работающее приложение. Прочитайте каждый файл, прежде чем напишете хотя бы строку собственного кода.

## # Вариант A (рекомендуется) — Помощник по документации / Q&A

Создайте систему, которая позволяет пользователю задавать вопросы по выбранному корпусу документов (документация, научные статьи, книга, кодовая база) и получать подкреплённые источниками ответы от агента, который также может вызывать инструменты (tools).

## # Option B — Research / news agentСоздайте агента, который, получив исследовательский вопрос, автономно планирует стратегию поиска, извлекает содержимое из нескольких источников, синтезирует отчёт и оценивает качество собственных результатов.

**Требуемые возможности:** планирование; веб/RSS (Really Simple Syndication) поиск (реальный или имитация); многошаговый цикл агента (модуль 06); современные агентские API или MCP (модуль 17); синтез с указанием источников (модуль 05); приёмка документов, если обрабатывается большой объём полученного содержимого (модуль 11); набор средств для оценки с регрессионным контролем (модули 07, 21), а также планировщик или триггер через CLI.

**Эскиз архитектуры**```
  User prompt ("Research X")
        │
        ▼
  Planner agent ──► subtask list (JSON)
        │
        ├─► Worker A: fetch + summarise source 1
        ├─► Worker B: fetch + summarise source 2
        └─► Worker C: ...          (run in parallel)
              │
              ▼
  Synthesiser agent ──► final report + citations
              │
              ▼
  Eval agent (LLM-as-judge) ──► factuality / coverage scores
              │
              ▼
  Regression gate (module 21) ──► CI check
```Примечание: `projects/news-agent` — это работающая реализация упрощённой версии этого паттерна. Изучите её, а затем расширьте или пересоберите с добавлением оценки, безопасности и улучшенного UX.

**Stretch goals:** доставка в Telegram, запуск по расписанию, режим сравнения, который отправляет один и тот же вопрос двум провайдерам и показывает различия в отчётах, укрепление безопасности (модуль 20) для ненадежного веб-контента.

## # Option C — Мультимодальный помощник

Создайте помощника, который объединяет зрение (модуль 09), аудио (модуль 19, опционально), приём документов (модуль 11), embeddings (модуль 04) и диалогового агента (модуль 06) для ответов на вопросы по смешанному мультимодальному корпусу.

**Required capabilities:** разбор документов и создание подписей к изображениям с помощью мультимодального LLM (модули 09, 11), создание embeddings для подписей/текста для поиска (модуль 04), RAG-пайплайн (Retrieval-Augmented Generation) по смешанным модальностям (модуль 05), агентский цикл с инструментами (модуль 06), укрепление безопасности (модуль 20) и система оценки (модули 07, 21).

**Architecture sketch**```
  Image + doc corpus
        │
        ▼ parse (module 11) + caption (module 09 multimodal LLM)
  Text captions + metadata
        │
        ▼ embed → vector store
  Query ──► retrieve captions ──► fetch image(s) ──► LLM answer + citations
```**Stretch goals:** поиск изображений в режиме zero-shot на основе CLIP (Contrastive Language-Image Pre-training) (module 09), транскрибация аудио из видео (module 19), этап подтверждения действий (modules 18/20), потоковая выдача + UI с цитированием (module 22).
